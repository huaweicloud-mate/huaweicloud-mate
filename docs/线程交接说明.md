## 1. 项目目标

构建一个通过公共 npm 一键安装的开源华为云 Agent 插件，让用户可以直接指挥 Agent 创建、修改、查询和删除华为云资源，例如创建并配置 ECS、OBS、IAM 和网络资源。

首版支持：

- OpenCode；
- Claude Code；
- Codex；
- 华为云码道；
- 内置本地 OBS provider；保留后续华为云产品 MCP 静态接入口；
- 自动安装或复用 KooCLI；
- 创建、修改、删除、IAM、网络和计费操作。

## 2. Proposed v0.3-lite 已确认决策

### 产品与发行

1. 单一 TypeScript npm package，通过公共 npm 发布。
2. 建议入口：`npx @huaweicloud/agent-plugin install`。
3. 默认用户级安装，不要求管理员权限。
4. 自动配置四类 Agent，不接受仅输出配置片段。
5. 首版不支持离线、HTTP/HTTPS 代理和 headless Linux。
6. `npx` 只作为安装入口；长期运行时物化到固定用户目录并通过稳定 launcher 启动。

### Tool Router

Agent 只看到三个固定工具：

```text
cloud_capabilities_search
cloud_capability_describe
cloud_action_execute
```

`status` 由 CLI `doctor/auth status` 承担；`plan` 合并到 execute 两阶段确认。

禁止：

- 任意 JavaScript/Python 执行；
- 任意 endpoint、命令或可执行路径；
- 通过 Tool 参数传入 AK/SK；
- 绕过能力清单的通用 OpenAPI 调用。

### Provider 与路由

1. 首版本地 OBS/KooCLI capability 数据随 npm 静态内置；后续产品 MCP 也只能通过新 npm 版本静态接入。
2. 不建设动态 Registry、签名、吊销或远程 denylist。
3. 不支持社区、第三方或用户自定义 Provider。
4. Tool 参数中的执行器选择只视为不可信偏好，Router 仍执行 capability、健康和风险校验。
5. 首版未指定时先选择支持该能力的本地 Provider，否则在执行前选择 KooCLI；后续产品 MCP 接入后仍保持 MCP 优先。
6. 生成 preview 或开始执行后锁定 executor。
7. 执行失败、超时或结果未知时不自动切换。

### 危险操作

- 只有普通 read 校验后直接执行；
- write 以及 `destructive / privileged / cost / sensitive-read` 复合风险首次 execute 返回 preview、摘要和 challenge；
- 固定受信签发器在明确用户操作后生成 `approvalReceipt`；
- 第二次 execute 只额外携带 `previewId`；Router 内部启动签发器，receipt 不进入 Agent 或 Tool 参数；
- receipt 绑定参数、executor、凭证代次、账号和作用域；Router 在 dispatch 前原子消费 preview。

### 凭证

1. 首版只有一个当前账号。
2. 用户首次使用时通过 `auth set` 只输入一组永久 AK/SK，可覆盖更新或删除；不要求密码、SecurityToken、SSO 或 profile 名。
3. AK/SK 保存到用户目录下权限受限的独立 `credentials.json`。
4. credentials 带随机 generation，Core 在执行和复用 session 前检查代次。
5. `auth set` 通过固定只读身份校验能力绑定非敏感 account/domain identity。
6. 不实现 OS Keyring。
7. 首版本地 OBS provider 只在进程内短会话接收 AK/SK；后续产品 MCP 通过同域 HTTPS credential session 接收。
8. Provider 只在内存保存最长 15 分钟，数据面使用 opaque session ID 和 route token。
9. `auth set/remove` 对已知 session 尽力撤销，不承诺无共享控制面的全局立即撤销。
10. 不建设独立凭证控制面、设备 mTLS、信封加密或 KMS/HSM。
11. 明确信任内置官方产品 MCP 及其 HTTPS 终止链路可以接触明文 AK/SK。

### KooCLI

1. 优先检测用户预装 KooCLI。
2. 版本兼容且 doctor 通过时复用。
3. 否则下载插件声明的固定版本，校验 SHA-256 后安装到私有用户目录。
4. 安装后执行版本、网络、认证和最小只读测试。
5. 不修改系统 KooCLI，不加入 PATH。

### 宿主适配与日志

1. 四宿主使用声明式模板，不设计通用 Adapter SPI。
2. 首版只提供 install、doctor、uninstall；重跑 install 完成升级。
3. 保留必要配置备份、失败回滚和最小 install-state。
4. 不提供独立 repair 或复杂 drift 检测。
5. 只记录本地脱敏 JSONL 日志，不上传遥测。
6. 四宿主模板必须绑定固定审批 issuer 和稳定 launcher。

## 3. 当前架构

```text
四类 Agent
  -> 声明式 MCP 配置 + Canonical Skills
  -> 本地 stdio Tool Router
       -> 静态能力清单
       -> 复合风险门禁 + 可信 approval receipt
       -> Product MCP Client -> 官方产品 MCP
       -> KooCLI Adapter -> 预装或私有 KooCLI

本地共享：
  单账号 credentials 文件
  credentials generation
  最小 install-state
  本地脱敏 JSONL 日志
```

Core 随 Agent session 启动，不安装常驻 daemon。

- MetaMCP 身份混淆；
- 开发机绝对路径；
- 运行时 `npx -y`；
- 任意代码 `mcp_execute`；
- Skill 与环境变量的写权限策略漂移。
