# 使用与故障诊断

本文说明 Proposed v0.3-lite 当前实现的安装、凭证、审批、卸载和故障恢复方式。仓库目前仍是开发候选：KooCLI 五平台正式制品、授权 argv invoker 和首个 ECS 只读 capability 已绑定，真实产品 MCP 已后置并保留接口；公共 npm 身份、四宿主隔离、KooCLI 元数据可用性和真实最小权限账号尚未完成发布验收。不要使用生产高权限凭证。

## 1. 开发候选准备

需要 Node.js 22，以及至少一个受支持宿主：Codex、Claude Code、OpenCode 或华为云码道。审批页需要可交互桌面和本机浏览器；首版不支持 headless Linux、代理或离线安装。

从源码验证当前候选：

```text
npm ci
npm test
npm run pack:check
```

后续公共 npm 版本发布后，`npx huaweicloud-mate install` 只负责安装入口；宿主长期配置始终指向用户目录中的稳定 launcher，不依赖 npm 临时缓存。

## 2. 安装与复验

自动发现并配置当前机器上的全部可用宿主：

```text
huaweicloud-mate install
```

只配置一个宿主：

```text
huaweicloud-mate install --host codex
huaweicloud-mate install --host claude
huaweicloud-mate install --host opencode
huaweicloud-mate install --host codearts
```

安装成功后应新建宿主会话，使宿主重新加载插件。重复运行同一版本的 `install` 会复验受管配置、资产、原生注册、运行时清单和 Router MCP 握手，不会静默覆盖同名的用户资产。跨版本安装会协调全部已发现宿主；只有所有候选内容验证成功后才切换一次 active pointer 并提交一次完整状态。

建议安装后依次运行：

```text
huaweicloud-mate doctor --contracts-only
huaweicloud-mate doctor --hosts
huaweicloud-mate doctor --koocli
huaweicloud-mate doctor --approval-probe
```

前三项不会读取云凭证或执行云操作。`--approval-probe` 会打开一次无云副作用的本机审批页，用于验证 companion 链路；审批只需点击，不要求输入密码。

## 3. 凭证

交互式设置当前唯一账号：

```text
huaweicloud-mate auth set
```

AK/SK 只从交互终端非回显读取，不接受普通命令行参数。当前开发态身份校验会执行固定 OBS `ListBuckets` 只读请求，因此账号至少需要 `obs:bucket:ListAllMyBuckets`，同时应保持最小权限。校验成功才会原子写入权限受限的 `credentials.json`；再次设置会更新非敏感的 credential generation，使旧 session 和旧 preview 失效。

查看不含密钥的状态或移除凭证：

```text
huaweicloud-mate auth status
huaweicloud-mate auth remove
```

卸载宿主插件不会删除凭证；如不再使用，必须另行运行 `auth remove`。不要手工编辑、复制或放宽凭证文件权限。

## 4. Agent 调用与审批

插件只暴露三个 MCP 工具：

- `cloud_capabilities_search`：搜索内置 capability；
- `cloud_capability_describe`：读取固定 schema、scope、风险和执行器信息；
- `cloud_action_execute`：执行普通读取，或启动危险操作的两阶段流程。

Agent 应先 search，再 describe，最后 execute。普通读取可直接完成。危险、敏感、特权、成本或写操作的首次 execute 只返回 preview；第二次调用重复原输入并携带 `previewId`。Router 随后在内部打开审批页、验签一次性 receipt、复核账号/scope/credential generation，并在 dispatch 前原子消费 preview。receipt、AK/SK 和 session 都不会进入 Agent 参数。

如果用户拒绝、参数变化、preview 过期、凭证更新或执行器发生变化，操作必须重新预览。创建或删除请求发出后连接中断会返回 `OUTCOME_UNKNOWN`；这表示结果不能安全判断，禁止自动重试，应先到云端查询实际状态。

首个 KooCLI 能力为 `huaweicloud.ecs.server.list.v1`。它要求 region、project 和 `limit`（1～50），可选 `marker` 用于分页；marker 必须与 limit 一起出现。该读取会展示 ECS ID、名称和状态，因此每次调用都需要点击审批。结果不包含地址、metadata、安全组等原始详情；当 `count < limit` 时分页结束，`count == limit` 时可用 `nextMarker` 发起下一页查询。

## 5. 卸载

卸载必须明确指定宿主：

```text
huaweicloud-mate uninstall --host codex
huaweicloud-mate uninstall --host claude
huaweicloud-mate uninstall --host opencode
huaweicloud-mate uninstall --host codearts
```

卸载只撤销本次安装拥有且 hash 未漂移的配置、注册和资产；不会删除共享 runtime、历史版本缓存或凭证。若内容已漂移或 ownership 无法证明，命令会 fail closed，而不是覆盖或删除用户修改。

## 6. 故障诊断与恢复

优先使用 JSON 报告保存机器可读证据：

```text
huaweicloud-mate doctor --hosts --json
huaweicloud-mate doctor --contracts-only --json
huaweicloud-mate auth status --json
```

常见处理：

- `not-detected`：宿主命令和固定配置路径都未发现；先安装或启动对应宿主。
- `available`：宿主可安装但当前没有受管状态；运行 `install`。
- `drifted`：配置、资产、注册或 Router 握手与 install-state 不一致；保留报告，不要手工删除状态，先重跑同版本 `install` 复验。
- ownership、hash 或 state conflict：说明无法证明安全覆盖或回滚；不要删除备份、quarantine 或 recovery marker，应保留现场排查。
- 多宿主升级中断：只运行不带 `--host` 的 `install`，让统一恢复标记先收敛旧版本或已提交候选；显式单宿主安装和卸载会拒绝绕过该恢复。
- `OUTCOME_UNKNOWN`：请求可能已到达云端；先查询实际资源，不要自动重复写入或删除。
- KooCLI unavailable：当前没有兼容系统/私有版本、未配置 AK/SK，或 capability 没有静态 KooCLI mapping。Router 会在执行前 fail closed。已授权 invoker 会把 AK/SK 放入直接子进程 argv，但不会放入普通环境变量、profile、插件日志或 Agent 上下文。

本地 Router 审计日志只记录固定元数据与参数/结果摘要，不记录凭证、session、审批 receipt 或对象正文。默认位置为：

- Windows：`%LOCALAPPDATA%\hcloud-agent\logs\router.jsonl`；
- macOS：`~/Library/Application Support/hcloud-agent/logs/router.jsonl`；
- Linux：`${XDG_DATA_HOME:-~/.local/share}/hcloud-agent/logs/router.jsonl`。

报告问题时可提供 doctor JSON、固定错误码和经过检查的日志元数据；不要提交 `credentials.json`、AK/SK、Authorization、签名 URL、对象正文或用户目录完整内容。
