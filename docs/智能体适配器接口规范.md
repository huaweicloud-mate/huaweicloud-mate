# 智能体宿主适配规范

状态：Proposed v0.3-lite
适用：OpenCode、Claude Code、Codex、华为云码道

## 1. 目的

首版不设计通用 Adapter SPI。四类宿主通过 npm 包内置的声明式模板完成：

- 宿主检测；
- 用户级 Router MCP 配置；
- Canonical Skills 安装；
- 固定可信审批签发器绑定；
- 安装后验证；
- 安全卸载。

云资源发现、路由、凭证、确认、产品 MCP 和 KooCLI 调用全部由本地 Core 实现。

## 2. 模板模型

每个宿主模板只描述安装所需数据：

```yaml
schemaVersion: huaweicloud-agent-host-template/v1-lite
id: codex
displayName: Codex
detect:
  commands: ["codex"]
  paths: []
mcp:
  configPath: "..."
  entryKey: "huaweicloud-agent"
  mergeStrategy: "json-object"
  launcher:
    ref: stable-runtime
    args: [router, --stdio]
skills:
  source: canonical
  targetPath: "..."
approval:
  mode: bundled-trusted-companion
  issuerId: huaweicloud-mate.local-approval
  verifierKeyId: local-approval-ed25519-v1
verify:
  type: config-process-skill
  requiresTrustedApprovalProbe: true
```

允许的 `mergeStrategy` 与固定 companion issuer/verifier key 必须由 Installer 内置实现。模板不能携带任意脚本、任意命令、动态下载地址或任意审批签发器。机器可读格式见 [host-template-v1-lite schema](契约/host-template-v1-lite.schema.json)。

`local-approval-ed25519-v1` 标识固定的 companion 验签协议和算法，不代表磁盘上的固定公钥；每次审批的临时公钥和 `approvalSessionId` 只能通过 Router 创建的私有父子 IPC 绑定。

## 3. Canonical Skills

仓库只维护一份 canonical source：

```text
skills/canonical/huaweicloud/
  SKILL.md
  references/
  assets/
```

构建时生成各宿主需要的目录布局。业务指导、风险说明和执行器选择规则只在 canonical source 维护，禁止四份手工复制长期独立演进。

Skills 可以指导 Agent 使用 search、describe 和 execute，但不能：

- 包含 AK/SK；
- 指定非内置 endpoint；
- 绕过 execute 确认；
- 直接调用任意 Shell；
- 修改 Core 风险规则。

## 4. 安装流程

```text
detect -> materialize stable runtime -> backup -> apply template/skills/approval -> verify -> write install-state
                                            |
                                            +---- failure ----> compare hash -> restore or report conflict
```

最小 `install-state.json`：

```json
{
  "schemaVersion": 1,
  "pluginVersion": "1.0.0",
  "installManifestSha256": "sha256:...",
  "runtimePath": ".../runtime/versions/1.0.0",
  "stableLauncherPath": ".../runtime/current/hcloud-agent.mjs",
  "hosts": [
    {
      "id": "codex",
      "mergeStrategy": "plugin-manifest",
      "configPath": "...",
      "entryKey": "huaweicloud-agent",
      "installedValueHash": "sha256:...",
      "approvalIssuerId": "huaweicloud-mate.local-approval",
      "asset": {
        "kind": "plugin",
        "targetPath": "...",
        "changed": true,
        "installedTreeHash": "sha256:...",
        "createdPaths": ["..."]
      }
    }
  ]
}
```

配置型宿主另含 `config` 事务证据；插件宿主的 `.mcp.json` 已包含在 asset tree hash 中，不重复建立配置 ownership。install-state 只用于安全卸载和失败回滚，不演进为通用 receipt、迁移或 drift 框架，也不提前写入尚未落地的 KooCLI 字段。

状态文件使用严格 schema、完整 runtime 清单复验、旧状态 SHA-256 compare-before-replace 和 hash 安全回滚。未来卸载仍必须把状态重新绑定到内置宿主计划，不能把状态中的绝对路径直接当作删除授权。

首装协调器要求原先不存在 install-state，按固定 host ID 顺序执行资产与配置事务。全部宿主完成后先只读复核配置文件 SHA-256 和资产 tree hash，再调用可选的真实宿主验证钩子；只有验证成功才把 install-state 作为最终提交点。失败时按宿主逆序、单宿主配置优先于资产进行回滚，并继续尝试其他独立回滚项。

提交前验证钩子会用稳定 launcher 执行精确版本 smoke test，并分别检查 Codex/Claude 的插件列表、OpenCode 的 MCP/Skill 列表，以及华为云码道的受管配置级证据；全部通过后再执行一次无云副作用的点击式审批探针。命令 runner 不使用 shell 或 stdin，默认 15 秒超时、输出最多 1 MiB，也不读取可能包含敏感数据的完整 debug config。该钩子只验证已经完成的注册，不负责写 marketplace；华为云码道在缺少稳定枚举接口时仍不能宣称进程级可发现。

首装失败会保留未被宿主引用的已验证 runtime 缓存；已有状态下的 runtime/active pointer 回退必须由后续受管升级事务处理。

## 5. 配置写入规则

- 只修改用户级配置；
- 保留未知字段、注释和用户格式能力能保留的部分；
- 同名 MCP 冲突时停止并报告，不静默覆盖；
- 写入前备份；
- 使用临时文件和原子替换，回滚前比较当前 hash，避免覆盖安装期间的用户修改；
- 备份使用当前用户专属权限，并定义保留期和安全清理；
- 不写入 AK/SK、session ID 或 credentials 路径；
- 不使用开发机绝对路径；
- Router 启动路径必须来自固定用户目录下的稳定 launcher，不得引用 npm 临时 cache；
- `npx` 只允许作为安装入口，Agent session 运行期不得执行 `npx -y`。

当前事务实现补充约束：

- `json-object` 和 `plugin-manifest` 必须是无注释的严格 JSON；`jsonc-object` 使用固定 `jsonc-parser@3.3.1` 做路径级编辑；
- 任意层级重复 property、非对象根、超过 8 MiB、符号链接或非普通文件均拒绝；
- 同名 `huaweicloud-agent` 完全相同时幂等，不同时返回 `HOST_CONFIG_CONFLICT`；首版没有 `--force`；
- 备份目录权限为 `0700`、备份文件为 `0600`；写入与回滚都在提交前复核完整文件 SHA-256；
- 回滚发现安装后文件或备份发生变化时返回 `HOST_CONFIG_ROLLBACK_CONFLICT`，不覆盖用户修改。

配置事务的机器结果包含安装前/后 hash、canonical entry hash、备份路径和 `createdFile`，后续原样进入最小 install-state。事务层当前明确拒绝未被四个内置模板采用的 `toml-table`。

宿主资产物化采用独立的有限事务：

- 复制前使用 active pointer 绑定的安装清单 digest 复验整个版本目录；
- 源路径只允许 `host-assets/<host>/plugin` 或 `skills/canonical/huaweicloud`；
- Codex/Claude 插件只在同级 staging 中渲染固定 Node 和 stable launcher，完成 manifest/MCP/Skill 复核后原子 rename；
- 目标目录已存在时只接受完整 tree hash 相同的幂等结果，不覆盖不同内容；
- 回滚先复核目标 hash，再通过 quarantine rename 和第二次 tree hash 防止删除竞态修改；
- 物化结果记录 `installedTreeHash` 和本次 `createdPaths`，供 install-state 与安全卸载使用。

当前物化层不负责 marketplace 注册、宿主配置写入或可发现性验证，也不支持没有 install-state 证明的受管目录升级替换。

建议运行时根目录：

- Windows：`%LOCALAPPDATA%\hcloud-agent\runtime`；
- macOS：`~/Library/Application Support/hcloud-agent/runtime`；
- Linux：`~/.local/share/hcloud-agent/runtime`。

实际版本位于 `versions/<pluginVersion>`，宿主只引用 `current` 下的稳定 launcher。当前 Node 运行时实现展开为固定 `process.execPath + current/hcloud-agent.mjs + [router, --stdio]`；未来可替换为 Windows 原生 `.exe` 包装而不改变 `stable-runtime` 模板语义。候选版本必须经过完整安装清单复验，升级只能在新版本 doctor 通过后原子切换 `active-runtime.json`。

## 6. 四宿主模板

当前内置模板绑定如下。`pluginRoot` 是 Installer 管理的稳定用户级插件目录，不是 npm cache；所有宿主最终都启动同一个 `runtime/current/hcloud-agent.mjs`。

| 宿主 | MCP 配置位置 | merge strategy | Canonical Skill 目标 |
| --- | --- | --- | --- |
| Codex | `~/plugins/huaweicloud-mate/.mcp.json` | `plugin-manifest` | `~/plugins/huaweicloud-mate/skills/huaweicloud` |
| Claude Code | `{pluginRoot}/.mcp.json` | `plugin-manifest` | `{pluginRoot}/skills/huaweicloud` |
| OpenCode | `~/.config/opencode/opencode.json` | `json-object` | `~/.config/opencode/skills/huaweicloud` |
| 华为云码道 | `~/.codeartsdoer/codearts_cli.jsonc` | `jsonc-object` | `~/.codeartsdoer/skills/huaweicloud` |

Codex/Claude 的源 `.mcp.json` 仅是随包模板；Installer 必须将其中的 Node 与 stable launcher 占位值替换为本机绝对路径后才可激活插件。OpenCode 与码道均生成宿主原生的 `mcp.huaweicloud-agent = { type: "local", command: [...], enabled: true }` 结构。

### 6.1 Codex

- 安装自包含 Codex plugin manifest；
- 将稳定插件目录固定到个人 marketplace 约定的 `~/plugins/huaweicloud-mate`；
- 注册一个本地 stdio Router MCP；
- 安装 Codex 可发现的 Skills 产物；
- 验证 manifest、Router 启动和 Skill 可发现性。

构建产物必须通过 Codex plugin manifest 校验，并保持 `.codex-plugin/plugin.json`、`.mcp.json` 与 `skills/` 自包含。个人 marketplace 文件固定为 `~/.agents/plugins/marketplace.json`，entry source 固定为 `./plugins/huaweicloud-mate`；专用事务只追加完整匹配的 `AVAILABLE / ON_INSTALL / Productivity` entry，并使用备份、原子替换和 hash 安全回滚。当前尚未调用 `codex plugin add`，entry 存在不等于插件已经激活。

### 6.2 Claude Code

- 生成自包含 Claude plugin；
- 通过 plugin MCP 配置注册本地 Router；
- 使用插件根或安装器生成的稳定路径；
- 安装 Skills 并验证 plugin cache 后路径。

插件布局固定为 `.claude-plugin/plugin.json`、根目录 `.mcp.json` 和 `skills/`，并以本机 `claude plugin validate` 兼容校验为门禁。

### 6.3 OpenCode

- 在用户级配置中注册本地 Router MCP；
- 安装 OpenCode 可发现的 Skills；
- 保留 JSON/JSONC 未知字段和可保留的注释；
- 首版不安装额外 Hook plugin。

用户级路径采用官方全局配置 `~/.config/opencode/opencode.json`；首版写入严格 JSON，同时保留未知字段。同名 `mcp.huaweicloud-agent` 不一致时停止，不覆盖。

### 6.4 华为云码道

- 在码道 CLI/桌面的用户级 MCP 配置中注册 Router；
- 安装码道可发现的 Skills；
- 首版不安装额外 Hook plugin；
- 验证 CLI 和桌面开发环境使用同一 Router/Skill 版本。

官方同时支持 `codearts_cli.json` 与 `codearts_cli.jsonc`。首版选择用户级 `.jsonc` 作为受管入口，后续写入器必须保留现有注释和未知字段。

### 6.5 可信审批

- 每个宿主模板必须绑定 npm 内置的固定 `issuerId` 和 verifier key ID；
- 四宿主统一使用 `huaweicloud-mate.local-approval` 受信 companion；签发器必须观察 companion 中的明确用户操作；
- Agent、Prompt、Skill、workspace 和普通 Tool 参数不能选择 issuer、替换 verifier 或自行签发 receipt；
- doctor 必须完成不产生云资源副作用的审批 challenge/receipt 探测；
- companion 每次审批使用仅存在于一次性进程内存的 Ed25519 密钥，通过 Router 创建的私有管道绑定临时公钥和 session ID；它不作为普通 Tool 暴露，也不提供自动批准或非交互签发路径。完成进程/IPC 验证前不得宣称危险操作确认是强制安全边界。

## 7. doctor

`hcloud-agent doctor` 至少检查：

- 宿主是否存在及版本是否可识别；
- MCP 配置是否指向当前 Router；
- MCP 配置是否指向稳定 launcher 而不是 npm cache；
- Router stdio 是否能启动并列出三个工具；
- Canonical Skills 是否可发现；
- credentials 文件权限是否合规；
- 产品 MCP 健康和 HTTPS 同源约束；
- Provider contract、capability/tool schema digest 是否与内置 descriptor 一致；
- 固定审批 issuer 与 verifier 是否有效；
- KooCLI 路径、版本、兼容范围和最小只读测试。

doctor 默认只读，不自动修复。

## 8. 重新安装与升级

重新运行 `install` 时：

1. 读取现有 install-state；
2. 备份当前宿主配置；
3. 把新运行时写入新的版本目录，不覆盖当前版本；
4. 写入新稳定 launcher 指针、模板、Skills 和审批绑定；
5. 运行 doctor；
6. 成功后原子替换 install-state 和 `current` 指针；
7. 失败时仅在配置 hash 未被外部修改时恢复备份和旧 install-state，否则保留现场并报告冲突。

首版不提供独立 `update` 或 `repair` 命令。

## 9. 卸载

`uninstall` 只能删除：

- install-state 中记录且 hash 未变化的 MCP 配置项；
- 本插件创建且未被用户修改的 Skills 目录；
- 插件私有 KooCLI 和缓存；
- 本插件自己的日志与状态文件。

默认保留 credentials 文件，提示用户可显式执行 `auth remove`。如果用户已修改目标配置，卸载只报告冲突，不强制删除。

## 10. 必测场景

- 四宿主全新安装和重复安装；
- 同名 MCP 冲突；
- 配置含未知字段、注释和非 ASCII 路径；
- Router/KooCLI 路径包含空格；
- 安装中断和 doctor 失败回滚；
- 安装期间用户修改配置时回滚不得覆盖用户内容；
- 四宿主可信审批 receipt 的签发、篡改、过期和重放；
- 稳定 launcher 不依赖 npm cache，升级失败仍可启动旧版本；
- 用户修改配置后的卸载；
- 重装升级后旧路径失效；
- 四个平台组合下的用户级路径和权限。
