# 智能体适配器接口规范

状态：Proposed v1  
适用：OpenCode、Claude Code、Codex、华为云码道及后续宿主

## 1. 目的

Adapter 只解决宿主安装与配置差异。所有云资源逻辑、Provider Registry、KooCLI、凭证、策略和审计都留在统一 Core。

## 2. 能力模型

```ts
export interface AgentHostCapabilities {
  mcp: {
    localStdio: boolean;
    remoteStreamableHttp: boolean;
    listChanged: boolean;
  };
  skills: {
    agentSkills: boolean;
    userScope: boolean;
    projectScope: boolean;
  };
  plugin: {
    nativeBundle: boolean;
    marketplace: boolean;
  };
  approvals: {
    nativeToolPolicy: boolean;
    hookMapping: boolean;
  };
  config: {
    userScope: boolean;
    projectScope: boolean;
    commentsPreserved: boolean;
  };
}
```

Core 的安全正确性不得依赖某项 capability 为 `true`。原生审批或 Hooks 只能提供额外体验与纵深防御。

## 3. SPI

```ts
export interface AgentAdapter {
  readonly id: string;
  detect(context: DetectContext): Promise<DetectionResult>;
  capabilities(): AgentHostCapabilities;
  planInstall(context: InstallContext): Promise<InstallPlan>;
  applyInstall(plan: InstallPlan): Promise<InstallReceipt>;
  verify(receipt: InstallReceipt): Promise<VerificationResult>;
  repair(receipt: InstallReceipt): Promise<InstallReceipt>;
  uninstall(receipt: InstallReceipt): Promise<void>;
}
```

所有操作必须满足：

- `planInstall` 只读；
- `applyInstall` 可重入、可恢复；
- `verify` 不修改状态；
- `uninstall` 只删除 receipt 证明由本插件创建的内容；
- 不覆盖用户未知字段，不删除用户已有 MCP/Skills/plugins；
- 同名冲突必须停止并给出解决方案，不能静默替换。

  "artifacts": [

    }

  "configMutations": [
    {
      "path": "...",

卸载时若目标值已被用户修改，只报告 drift，不主动删除。

## 5. Canonical assets

仓库只维护一份 canonical Skills 和 Router 启动定义：

```text
skills/canonical/huaweicloud/
  SKILL.md
  references/
  scripts/
```

构建阶段根据宿主约束生成 adapter artifact。禁止四份手工复制的 Skill 长期独立演进。

## 6. 首版 Adapter 行为

### 6.1 Codex

- 生成自包含 `.codex-plugin/plugin.json`；
- 注册一个本地 stdio Router MCP；
- 安装 canonical Skills 的 Codex 产物；
- 所有可执行路径来自安装 receipt，不得硬编码开发机绝对路径；
- 验证 plugin manifest、MCP 启动和 Skill 可发现性。

### 6.2 Claude Code

- 生成自包含 `.claude-plugin/plugin.json`；
- 通过 plugin `mcpServers` 注册本地 Router；
- 使用 `${CLAUDE_PLUGIN_ROOT}` 或安装器生成的稳定路径；
- 安装 Skills，不依赖包目录之外的相对文件；
- 支持插件 cache 后的路径验证和 reload 指引。

### 6.3 OpenCode

- 在用户级配置中注册本地 MCP；
- 安装 `.opencode/skills` 或兼容的全局 Skills；
- 可选安装薄 JS/TS plugin 以增强 doctor/权限体验，但 Core 不依赖该 plugin；
- 保留用户 JSON/JSONC 的注释与未知字段。

### 6.4 华为云码道

- 以码道 CLI/桌面的用户级 MCP 配置注册 Router；
- 安装 `~/.codeartsdoer/skills` 产物；
- 可选生成 JS/TS hook plugin 映射宿主审批，但不把安全策略放进 Hook；
- 验证 CLI 和桌面开发环境可以发现同一个 Router/Skill 版本。

## 7. 安装事务

```text
detect -> plan -> confirm -> backup -> stage -> validate -> atomic swap -> verify -> receipt
                                      |
                                      +----failure----> rollback
```

Adapter 不直接下载 KooCLI，也不处理 AK/SK；这些由 Installer/Core 的共享模块完成。

## 8. 新增宿主流程

新增 Agent 必须：

1. 实现 SPI 和 capability 声明；
2. 提供 user-scope 配置映射；
3. 通过 install/update/repair/uninstall 幂等测试；
4. 通过不覆盖既有用户配置的 fixture tests；
5. 运行 Router MCP 与 canonical Skill smoke test；
6. 加入宿主版本兼容矩阵。

不允许新增宿主时复制 Core、Provider client 或 KooCLI adapter。

## 9. 兼容性策略

- 每个 Adapter 声明 `minHostVersion` 与已验证版本范围；
- 未验证的新宿主版本可以警告后继续只读 doctor，但默认不执行破坏性配置迁移；
- 宿主配置 schema 改变时发布新的 Adapter 版本，不要求 Core 同步大版本；
- receipt 记录 Adapter 版本，使 repair/uninstall 使用相同迁移规则。

## 10. 必测场景

- 全新安装、重复安装、部分安装失败恢复；
- 用户已有同名/异名 MCP；
- 配置文件带注释、未知字段和格式差异；
- Core/KooCLI 路径包含空格和非 ASCII 字符；
- 更新后路径变化、宿主 cache 未刷新；
- 用户手工修改已安装配置后的 repair/uninstall；
- 四个平台下 user-scope 路径和权限。
