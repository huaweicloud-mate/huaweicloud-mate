# 智能体宿主适配规范

状态：Proposed v0.3-lite
适用：OpenCode、Claude Code、Codex、华为云码道

## 1. 目的

首版不设计通用 Adapter SPI。四类宿主通过 npm 包内置的声明式模板完成：

- 宿主检测；
- 用户级 Router MCP 配置；
- Canonical Skills 安装；
- 固定可信审批签发器绑定；
- 安装后验证；
- 安全卸载。

云资源发现、路由、凭证、确认、产品 MCP 和 KooCLI 调用全部由本地 Core 实现。

## 2. 模板模型

每个宿主模板只描述安装所需数据：

```yaml
schemaVersion: huaweicloud-agent-host-template/v1-lite
id: codex
displayName: Codex
detect:
  commands: ["codex"]
  paths: []
mcp:
  configPath: "..."
  entryKey: "huaweicloud-agent"
  mergeStrategy: "json-object"
  launcher:
    ref: stable-runtime
    args: [router, --stdio]
skills:
  source: canonical
  targetPath: "..."
approval:
  mode: bundled-trusted-companion
  issuerId: huaweicloud-mate.local-approval
  verifierKeyId: local-approval-ed25519-v1
verify:
  type: config-process-skill
  requiresTrustedApprovalProbe: true
```

允许的 `mergeStrategy` 与固定 companion issuer/verifier key 必须由 Installer 内置实现。模板不能携带任意脚本、任意命令、动态下载地址或任意审批签发器。机器可读格式见 [host-template-v1-lite schema](契约/host-template-v1-lite.schema.json)。

## 3. Canonical Skills

仓库只维护一份 canonical source：

```text
skills/canonical/huaweicloud/
  SKILL.md
  references/
  assets/
```

构建时生成各宿主需要的目录布局。业务指导、风险说明和执行器选择规则只在 canonical source 维护，禁止四份手工复制长期独立演进。

Skills 可以指导 Agent 使用 search、describe 和 execute，但不能：

- 包含 AK/SK；
- 指定非内置 endpoint；
- 绕过 execute 确认；
- 直接调用任意 Shell；
- 修改 Core 风险规则。

## 4. 安装流程

```text
detect -> materialize stable runtime -> backup -> apply template/skills/approval -> verify -> write install-state
                                            |
                                            +---- failure ----> compare hash -> restore or report conflict
```

最小 `install-state.json`：

```json
{
  "schemaVersion": 1,
  "pluginVersion": "1.0.0",
  "runtimePath": ".../runtime/versions/1.0.0",
  "stableLauncherPath": ".../runtime/current/hcloud-agent",
  "hosts": [
    {
      "id": "codex",
      "configPath": "...",
      "entryKey": "huaweicloud-agent",
      "installedValueHash": "...",
      "approvalIssuerId": "huaweicloud-mate.local-approval",
      "createdPaths": ["..."],
      "backupPath": "..."
    }
  ],
  "koocliPath": "...",
  "koocliSource": "preinstalled"
}
```

install-state 只用于安全卸载和失败回滚，不演进为通用 receipt、迁移或 drift 框架。

## 5. 配置写入规则

- 只修改用户级配置；
- 保留未知字段、注释和用户格式能力能保留的部分；
- 同名 MCP 冲突时停止并报告，不静默覆盖；
- 写入前备份；
- 使用临时文件和原子替换，回滚前比较当前 hash，避免覆盖安装期间的用户修改；
- 备份使用当前用户专属权限，并定义保留期和安全清理；
- 不写入 AK/SK、session ID 或 credentials 路径；
- 不使用开发机绝对路径；
- Router 启动路径必须来自固定用户目录下的稳定 launcher，不得引用 npm 临时 cache；
- `npx` 只允许作为安装入口，Agent session 运行期不得执行 `npx -y`。

建议运行时根目录：

- Windows：`%LOCALAPPDATA%\hcloud-agent\runtime`；
- macOS：`~/Library/Application Support/hcloud-agent/runtime`；
- Linux：`~/.local/share/hcloud-agent/runtime`。

实际版本位于 `versions/<pluginVersion>`，宿主只引用 `current/hcloud-agent`（Windows 为 `.exe`）稳定 launcher。升级只能在新版本 doctor 通过后原子切换 `current`。

## 6. 四宿主模板

### 6.1 Codex

- 安装自包含 Codex plugin manifest；
- 注册一个本地 stdio Router MCP；
- 安装 Codex 可发现的 Skills 产物；
- 验证 manifest、Router 启动和 Skill 可发现性。

### 6.2 Claude Code

- 生成自包含 Claude plugin；
- 通过 plugin MCP 配置注册本地 Router；
- 使用插件根或安装器生成的稳定路径；
- 安装 Skills 并验证 plugin cache 后路径。

### 6.3 OpenCode

- 在用户级配置中注册本地 Router MCP；
- 安装 OpenCode 可发现的 Skills；
- 保留 JSON/JSONC 未知字段和可保留的注释；
- 首版不安装额外 Hook plugin。

### 6.4 华为云码道

- 在码道 CLI/桌面的用户级 MCP 配置中注册 Router；
- 安装码道可发现的 Skills；
- 首版不安装额外 Hook plugin；
- 验证 CLI 和桌面开发环境使用同一 Router/Skill 版本。

### 6.5 可信审批

- 每个宿主模板必须绑定 npm 内置的固定 `issuerId` 和 verifier key ID；
- 四宿主统一使用 `huaweicloud-mate.local-approval` 受信 companion；签发器必须观察 companion 中的明确用户操作；
- Agent、Prompt、Skill、workspace 和普通 Tool 参数不能选择 issuer、替换 verifier 或自行签发 receipt；
- doctor 必须完成不产生云资源副作用的审批 challenge/receipt 探测；
- companion 使用每安装实例独立 Ed25519 密钥，不作为普通 Tool 暴露，也不提供自动批准或非交互签发路径；完成实现验证前不得宣称危险操作确认是强制安全边界。

## 7. doctor

`hcloud-agent doctor` 至少检查：

- 宿主是否存在及版本是否可识别；
- MCP 配置是否指向当前 Router；
- MCP 配置是否指向稳定 launcher 而不是 npm cache；
- Router stdio 是否能启动并列出三个工具；
- Canonical Skills 是否可发现；
- credentials 文件权限是否合规；
- 产品 MCP 健康和 HTTPS 同源约束；
- Provider contract、capability/tool schema digest 是否与内置 descriptor 一致；
- 固定审批 issuer 与 verifier 是否有效；
- KooCLI 路径、版本、兼容范围和最小只读测试。

doctor 默认只读，不自动修复。

## 8. 重新安装与升级

重新运行 `install` 时：

1. 读取现有 install-state；
2. 备份当前宿主配置；
3. 把新运行时写入新的版本目录，不覆盖当前版本；
4. 写入新稳定 launcher 指针、模板、Skills 和审批绑定；
5. 运行 doctor；
6. 成功后原子替换 install-state 和 `current` 指针；
7. 失败时仅在配置 hash 未被外部修改时恢复备份和旧 install-state，否则保留现场并报告冲突。

首版不提供独立 `update` 或 `repair` 命令。

## 9. 卸载

`uninstall` 只能删除：

- install-state 中记录且 hash 未变化的 MCP 配置项；
- 本插件创建且未被用户修改的 Skills 目录；
- 插件私有 KooCLI 和缓存；
- 本插件自己的日志与状态文件。

默认保留 credentials 文件，提示用户可显式执行 `auth remove`。如果用户已修改目标配置，卸载只报告冲突，不强制删除。

## 10. 必测场景

- 四宿主全新安装和重复安装；
- 同名 MCP 冲突；
- 配置含未知字段、注释和非 ASCII 路径；
- Router/KooCLI 路径包含空格；
- 安装中断和 doctor 失败回滚；
- 安装期间用户修改配置时回滚不得覆盖用户内容；
- 四宿主可信审批 receipt 的签发、篡改、过期和重放；
- 稳定 launcher 不依赖 npm cache，升级失败仍可启动旧版本；
- 用户修改配置后的卸载；
- 重装升级后旧路径失效；
- 四个平台组合下的用户级路径和权限。
