# 首版实施路线图

状态：Proposed v0.3-lite

当前里程碑：M0 契约保持 Draft；已授权并行进入 M1 工程基础实现。开发态 reference provider 用于解除本地开发阻塞，不替代 M3 的真实产品 MCP 验收。

## M0：精简契约冻结

交付：

- 三个 Router tool schema；
- Capability schema v1-lite：`operationKind + riskTags + confirmationRequired`；
- 内置 Provider descriptor、兼容握手与 schema digest；
- HTTPS credential session v1：credentials generation、route token 和最长 900 秒撤销窗口；
- execute preview、可信 `approvalReceipt` 与原子消费状态机；
- 四宿主声明式模板、固定审批 issuer 与稳定 launcher；
- KooCLI 兼容、私有安装和受控调用策略；
- 正反例、重放、失配和 `OUTCOME_UNKNOWN` 测试向量；
- 3～5 个端到端验收场景清单。

退出标准：

- reference provider 的开发/测试边界明确，并通过 descriptor、credential session、route token 和兼容握手契约测试；
- 真实产品 MCP 清单、endpoint 与责任人可推迟到 M3 集成前绑定，但未绑定时契约不得标记 Frozen；
- `auth set` 固定只读身份校验能力明确，并能绑定 credentials generation 与 account identity；
- 四宿主统一绑定 `huaweicloud-mate.local-approval` 受信 companion，且 Agent 不能自行签发 receipt；
- KooCLI 固定版本、兼容范围和 SHA-256 清单明确；
- search、describe、execute 的输入输出冻结；
- capability 复合风险、敏感读取和输出脱敏规则冻结；
- schema 与测试向量通过独立 JSON Schema 校验器；
- 任意代码执行、任意 endpoint 和凭证 Tool 参数被明确禁止。

## M1：单包基础与安装器

交付：

- 单一 TypeScript npm package、CI 和公共 npm 发布流水线；
- `install`、`doctor`、`uninstall`；
- 单账号 `auth set/status/remove`；
- 权限受限 credentials 文件；
- 固定用户目录下的版本化运行时、稳定 launcher 和原子 `current` 切换；
- KooCLI 检测、复用、下载、SHA-256 和 doctor；
- 最小 install-state、配置备份和失败回滚；
- 本地 JSONL 日志基础。

已完成的开发切片包括私有开发包骨架、契约注册/校验、CLI/doctor、stdio MCP 三工具服务、静态开发态 capability catalog、reference executor，以及审批 companion 的一次性内存 Ed25519 密钥、session binding、runtime manifest/SHA-256、私有父子 IPC、本地浏览器 UI、receipt 签发/验签、时效与一次性消费核心。最小 Router 已接入 preview、受信内部 review、receipt 精确绑定、执行器锁定、凭证代次校验、dispatch 前原子消费和 JSON Pointer 输出脱敏；`doctor --approval-probe` 已接入同一无云副作用链路。版本化运行时核心已实现自包含 Router/companion bundle、完整安装清单、staging 复验、稳定 launcher、原子 active pointer、重复安装复用及篡改 fail closed。宿主配置/资产事务、最小 install-state 状态信封和首装逆序失败回滚编排也已实现，但尚未接入真实宿主注册/可发现性验证或 install/uninstall；当前不接收真实 AK/SK、不执行云资源操作，也不建立公共 npm 发布流水线。

退出标准：

- 无管理员权限完成用户级安装；
- 兼容预装 KooCLI 能复用；
- 不兼容时私有版本安装并通过最小只读测试；
- AK/SK 不进入参数、workspace 或日志；
- 不支持环境由 doctor 明确报告。

## M2：Router 与双执行器

交付：

- `cloud_capabilities_search`；
- `cloud_capability_describe`；
- `cloud_action_execute`；
- 静态内置能力清单；
- 产品 MCP Client 与 HTTPS credential session；
- KooCLI Adapter；
- MCP 优先、KooCLI 补位的执行前路由；
- 复合风险、可信 approval receipt、preview 原子消费、执行器锁定和 `OUTCOME_UNKNOWN`。

审批 launcher 和 UI 已接入最小 Router 核心与 `doctor --approval-probe`；stdio MCP 已只暴露三个工具，并完成开发态 search/describe/普通 read/危险两阶段调用、结构化错误和输出脱敏验证。ADR-0010 已冻结第二次调用只携带 `previewId`、Router 内部完成 companion review 与回执验签的协议；ADR-0011 已完成版本目录、完整 manifest 和稳定 launcher 的本地闭环。正式 capability catalog、真实 Provider/KooCLI dispatch、发布 provenance/目录 ACL，以及四宿主同账号进程与 loopback 隔离仍待实现。自动化测试使用无云副作用 fixture，四宿主真实交互探测仍是发布门禁。

退出标准：

- Agent 只看到三个工具；
- 产品 MCP 与 KooCLI 能力可搜索和描述；
- 只有无风险普通 read 可直接执行；
- write/destructive/privileged/cost/sensitive-read 必须获得可信审批；
- 失败和结果未知不自动切换执行器；
- credential session 过期、撤销、重启和账号不匹配测试通过。

## M3：四宿主与首发产品

交付：

- Codex、Claude Code、OpenCode、华为云码道声明式模板；
- 四宿主固定审批签发器集成；
- Canonical Skills 及四宿主构建产物；
- 自动配置、验证和安全卸载；
- 首发产品 MCP descriptor 与 capability 数据；
- KooCLI 对未覆盖核心服务的能力映射；
- 3～5 个端到端场景。

退出标准：

- 四宿主完成相同的 Router/Skill 启动验证；
- 至少一个产品 MCP 完成真实资源操作；
- ECS、OBS 等核心场景按最终清单通过；
- 创建、修改、删除、IAM、网络、计费和敏感读取覆盖可信审批门禁；
- 安装失败能够恢复宿主配置。

## M4：发布加固

交付：

- Windows amd64、Linux amd64/arm64、macOS amd64/arm64 测试；
- credentials 文件权限与泄漏扫描；
- 产品 MCP 凭证日志/trace/磁盘扫描；
- approval receipt 篡改、重放、并发消费和 issuer 替换测试；
- KooCLI 命令注入、超时和结果未知测试；
- npm SBOM、许可证、漏洞、secret 和 provenance；
- 安装、凭证、危险操作、卸载和故障诊断文档；
- 首个开源版本发布候选。

退出标准：

- 技术架构首版验收基线全部通过；
- 公开仓库不包含凭证、内部 endpoint 或开发机路径；
- npm 安装包内容与源码发布标签一致；
- 产品 MCP 团队确认 AK/SK 内存会话责任边界。

## 测试矩阵

平台：

- Windows amd64；
- Linux amd64/arm64；
- macOS amd64/arm64。

宿主：

- OpenCode；
- Claude Code；
- Codex；
- 华为云码道。

执行器：

- 内置产品 MCP；
- 兼容的预装 KooCLI；
- 插件私有固定 KooCLI；
- 产品 MCP 未覆盖或执行前不可用；
- 执行开始后的超时和结果未知。

风险：

- read；
- write；
- destructive；
- privileged；
- cost。
- sensitive-read；
- write + cost + privileged 等复合风险。

## 实施前外部输入

- 公共 npm scope 与发布身份；
- 首发真实产品 MCP 清单和 endpoint；
- 产品 MCP capability 复合风险、输出策略和 schema digest；
- 产品 MCP credential session 实现责任人；
- `auth set` 固定只读账号身份校验能力和责任人；
- 统一受信审批 companion 的四宿主进程/loopback 隔离验证和交互责任人；
- KooCLI 兼容范围、固定版本与 SHA-256；
- 3～5 个端到端验收场景。

## 不进入首版

- 动态 Provider Registry、签名、吊销和远程 denylist；
- 第三方或社区 Provider；
- OS Keyring 和多账号 target；
- 独立凭证控制面、mTLS、信封加密和 KMS/HSM；
- 企业策略中心、集中审计和遥测；
- 独立 update/repair 和复杂 drift 检测；
- 离线、HTTP/HTTPS 代理和 headless Linux；
- 常驻本地 daemon；
- 任意代码工作流执行器；
- 全量 OpenAPI 在 Agent 侧展开为工具。
