# 首版实施路线图

状态：Proposed v0.3-lite

当前里程碑：M0 契约保持 Draft；已授权并行进入 M1 工程基础实现。ADR-0048 已确认真实产品 MCP 后置，首版以本地 OBS provider、KooCLI 和保留的静态产品 MCP 接入口推进。

## M0：精简契约冻结

交付：

- 三个 Router tool schema；
- Capability schema v1-lite：`operationKind + riskTags + confirmationRequired`；
- 内置 Provider descriptor、兼容握手与 schema digest；
- HTTPS credential session v1：credentials generation、route token 和最长 900 秒撤销窗口；
- execute preview、可信 `approvalReceipt` 与原子消费状态机；
- 四宿主声明式模板、固定审批 issuer 与稳定 launcher；
- KooCLI 兼容、私有安装和受控调用策略；
- 正反例、重放、失配和 `OUTCOME_UNKNOWN` 测试向量；
- 3～5 个端到端验收场景清单。

ADR-0031 已在同一 OBS Provider 边界内补充受审批的空桶删除；删除连接中断按 `OUTCOME_UNKNOWN` 处理且不重试，因此本地替身已覆盖查询、创建与删除的最小资源生命周期。

ADR-0032 已完成真实 stdio Router 的权限受限 JSONL 日志、固定脱敏字段、参数/结果摘要、Agent/版本绑定、有界轮转，以及 dispatch 前后日志故障语义；本地日志基础不再是待实现项。

ADR-0033 已完成用户级 runtime 的递归权限门禁：安装写入前和卸载读取状态前都会覆盖版本、状态、恢复/备份证据及私有 KooCLI；Windows 当前 SID ACL 已通过真实临时目录测试，POSIX owner/mode 与异常树保持 fail closed。

ADR-0034 已完成 OpenCode/码道跨版本受管升级：稳定配置与最初 rollback backup 不重写，Canonical Skill 按 ownership/hash 替换，旧 state/候选 state、active pointer 和随机 quarantine 在严格恢复标记下保守收敛。四宿主现在都支持重跑 install 完成升级。

ADR-0035 已把最初 3 个 M0 状态机向量接入真实无云 Router/session harness，并为 Provider handshake digest 增加语义拒绝验证；ADR-0046 又加入产品 MCP 执行前不可用时选择安全 KooCLI Adapter 的真实向量。正式构建 doctor 现报告 9 个 schema 向量、4 个状态机向量、0 个 deferred。

ADR-0036 已在 JSON Pointer 脱敏之后增加未声明凭证材料兜底拒绝；凭证字段、Authorization/安全令牌、签名 URL、SDK/OBS 授权串和 PEM 私钥标记不得未经完整脱敏进入 Agent。

ADR-0037 已让稳定 launcher 从校验时保留的 `runtime/cli.js` 内存字节加载主 CLI，并一次性绑定逻辑 `import.meta.url` 到已验证版本目录；入口文件不再在 SHA-256 校验后被按路径二次读取。

ADR-0038 已让正式审批 launcher 经私有 stdin 把已验签 companion 入口字节交给固定无签名能力 bootstrap，并在内部 ready 后才发送 review；入口源码、审批上下文和密钥不进入 argv/环境变量。

ADR-0039 已让 launcher 在同一轮验签中保留七份冻结契约文本，父端 verifier 与子端 signer 分别从同一批内存文本编译 registry；正式审批不再在摘要校验后按路径重读 schema。

ADR-0040 已补充本地 OBS 有界文本对象敏感读取：固定 endpoint/key 语法、MIME allowlist、fatal UTF-8、64 KiB 上限、点击审批前零 dispatch，以及审批后 credential-like 内容仍 fail closed。至此首版本地真实 Router 路径已覆盖普通读取、敏感读取、成本/权限写入和破坏性写入；它不冒充正式产品 MCP，仍需真实最小权限账号验收。

ADR-0041 已收敛 companion 本地进程与 loopback 面：显式禁用 SIGUSR1 inspector、拒绝 Node 注入/转储环境、随机审批页面只成功读取一次，并严格限制 loopback/Host/Origin/CSRF/表单及时限。真实四宿主对浏览器 URL、私有 IPC 和 OS 调试的 sandbox 隔离仍需实际会话证明。

ADR-0042 已删除停用的文件规划记录与开发机绝对路径，并把源码卫生检查接入 CI、release candidate 和 prepublish；它与 Git 历史 gitleaks、npm pack allowlist 分别覆盖当前树、历史和发布包，避免用本机值填充尚未绑定的正式输入。

ADR-0043 已新增 `doctor --hosts`：无凭证、无审批、无云访问地识别四宿主，并对受管状态复验配置/资产、原生注册和稳定 Router MCP 握手；未安装、健康、漂移和不支持环境有固定状态与退出语义，报告不泄露本地路径。

ADR-0044 已让无 `--host` 的 `install` 自动发现全部可安装宿主，并复用既有一至四宿主原子首装事务；多宿主同版本重跑会完整复验且保持 state/pointer 不变。

ADR-0045 已完成跨版本多宿主协调升级：统一恢复标记绑定全部候选资产、Claude catalog 和插件 activation，所有宿主就绪后只切一次 active pointer、只提交一次完整 install-state；最终验证失败全局回滚，旧 state 与候选 state 两类中断现场会在下一次自动 install 保守收敛。

ADR-0046 已完成 KooCLI Router Adapter 的固定 capability 映射、无原始凭证的受信调用接口、执行前 MCP 优先/KooCLI 补位、结构化结果和错误归一化。ADR-0048 已绑定官方页面的 `7.2.12` 五平台制品与 SHA-256；ADR-0050 又在用户明确接受进程列表风险后绑定无配置 argv invoker。ADR-0051 已加入首个 ECS 列表 capability、敏感读取审批和固定输出裁剪。当前剩余项是 KooCLI 元数据可用性与最小权限账号验收。

ADR-0048 同时确认真实产品 MCP 不进入首版；静态 descriptor、Streamable HTTP client、credential-session、health/digest 和 MCP 优先路由接口继续保留，后续通过新插件版本接入。

正式 Windows amd64 KooCLI 包已通过项目私有安装器完成 archive/executable 双摘要、安全解包、原子提交和 `7.2.12` 复验；版本探测后的短暂 Windows `EPERM/EBUSY` 采用有界退避，不放宽目标冲突或未知错误语义。

安装、凭证、危险操作、卸载、中断恢复和故障诊断已汇总为 `docs/使用与故障诊断.md`，并明确开发候选、真实云验收和正式发布之间的边界。

ADR-0047 已把 npm pack allowlist 扩展为真实 tarball 隔离消费门禁：离线安装生产依赖、验证 package/bin 绑定，并只通过已安装 bin 运行版本与零 deferred 契约 Doctor；源码树通过但发布包不可消费时会在候选阶段失败。

退出标准：

- reference provider 的开发/测试边界明确，并通过 descriptor、credential session、route token 和兼容握手契约测试；
- 真实产品 MCP 清单、endpoint 与责任人移至首版后的集成输入，不再阻塞首版契约；
- `auth set` 固定只读身份校验能力明确，并能绑定 credentials generation 与 account identity；
- 四宿主统一绑定 `huaweicloud-mate.local-approval` 受信 companion，且 Agent 不能自行签发 receipt；
- KooCLI 固定版本、兼容范围和 SHA-256 清单明确；已由 ADR-0048 完成；
- search、describe、execute 的输入输出冻结；
- capability 复合风险、敏感读取和输出脱敏规则冻结；
- schema 与测试向量通过独立 JSON Schema 校验器；
- 任意代码执行、任意 endpoint 和凭证 Tool 参数被明确禁止。

## M1：单包基础与安装器

交付：

- 单一 TypeScript npm package、CI 和公共 npm 发布流水线；
- `install`、`doctor`、`uninstall`；
- 单账号 `auth set/status/remove`；
- 权限受限 credentials 文件；
- 固定用户目录下的版本化运行时、稳定 launcher 和原子 `current` 切换；
- KooCLI 检测、复用、下载、SHA-256 和 doctor；
- 最小 install-state、配置备份和失败回滚；
- 本地 JSONL 日志基础。

已完成的开发切片包括私有开发包骨架、契约注册/校验、CLI/doctor、stdio MCP 三工具服务、静态 capability catalog、reference executor，以及审批 companion 的一次性内存 Ed25519 密钥、session binding、runtime manifest/SHA-256、私有父子 IPC、本地浏览器 UI、receipt 签发/验签、时效与一次性消费核心。最小 Router 已接入 preview、受信内部 review、receipt 精确绑定、执行器锁定、凭证代次校验、dispatch 前原子消费和 JSON Pointer 输出脱敏；`doctor --approval-probe` 已接入同一无云副作用链路。版本化运行时核心已实现自包含 Router/companion bundle、完整安装清单、staging 复验、稳定 launcher、原子 active pointer、重复安装复用及篡改 fail closed。宿主配置/资产事务、最小 install-state 状态信封、首装逆序失败回滚、四宿主只读验证钩子，以及 Codex 个人 marketplace 文件事务、结构化 CLI 激活/回滚和状态证据已实现。Codex 与 Claude 单宿主 `install/uninstall` CLI 已完成运行时物化、宿主验证、点击式无云审批探针、固定路径重绑定、ownership 预检、安全逆序清理、受管升级、常规失败回滚和强制终止后的保守恢复；Claude 恢复还能发现 CLI 结果未知但实际已安装的候选，并在恢复旧 activation 后安全更新 install-state 证据。OpenCode/码道配置、Skill、状态及卸载事务入口已完成。已验证 runtime 与 credentials 在卸载时保留。单账号 `auth set/status/remove`、非回显录入、权限受限凭证文件、generation、原子 CAS 和固定只读账号校验已实现；Windows ACL 与 POSIX 权限策略均有测试。内置本地 OBS provider 已实现固定 endpoint 的 `ListBuckets`、受审批的有界文本对象读取、私有桶创建和空桶删除、官方 header 签名、受限 XML/文本解析、最长 900 秒进程内 session、账号漂移检查，以及 Router search/describe/execute 测试。KooCLI 已完成预装优先选择、版本发现、`doctor --koocli`、五平台制品绑定校验、安全解包、SHA-256、版本化私有目录、原子安装、篡改复核、授权 argv invoker 和首个 ECS 只读 capability；ADR-0048 已绑定官方 `7.2.12` 五平台下载对象与摘要，ADR-0050 已绑定无 profile、无 shell、零重试的凭据执行，ADR-0051 已绑定敏感读取审批和固定裁剪输出。当前 Windows amd64 开发机的系统 KooCLI `7.2.12` 也已被真实 doctor 识别为 compatible/system。五平台 GitHub Actions CI、pack 内容/大小、生产许可、漏洞、secret、CycloneDX SBOM、build provenance 和受保护的手动 npm 发布 workflow 已完成；npm 身份仍保持 private/development fail closed。四宿主提交前已补齐稳定 Router 的真实 MCP 进程握手；KooCLI 元数据/最小权限账号、码道真实会话加载与隔离验收仍未完成。

退出标准：

- 无管理员权限完成用户级安装；
- 兼容预装 KooCLI 能复用；
- 不兼容时私有版本安装并通过最小只读测试；
- AK/SK 不进入参数、workspace 或日志；
- 不支持环境由 doctor 明确报告。

## M2：Router 与双执行器

交付：

- `cloud_capabilities_search`；
- `cloud_capability_describe`；
- `cloud_action_execute`；
- 静态内置能力清单；
- 本地 OBS provider；保留但不激活的产品 MCP Client 与 HTTPS credential-session 接口；
- KooCLI Adapter；
- 本地 Provider/KooCLI 的执行前路由，以及后续 MCP 优先入口；
- 复合风险、可信 approval receipt、preview 原子消费、执行器锁定和 `OUTCOME_UNKNOWN`。

审批 launcher 和 UI 已接入最小 Router 核心与 `doctor --approval-probe`；stdio MCP 已只暴露三个工具，并完成 search/describe、reference read、本地 OBS 普通读取、敏感读取、创建与删除两阶段调用、结构化错误和输出脱敏/凭证兜底拒绝验证。ADR-0010 已冻结第二次调用只携带 `previewId`、Router 内部完成 companion review 与回执验签的协议；ADR-0011 已完成版本目录、完整 manifest 和稳定 launcher 的本地闭环，ADR-0033 已完成安装/卸载边界的用户级 runtime 递归权限门禁，ADR-0037 已关闭主 CLI 校验后按路径二次读取的窗口。本地 OBS capability 与 provider dispatch 已实现；KooCLI argv dispatch 边界已实现，首个真实 mapping、发布 provenance，以及四宿主同账号进程与 loopback 隔离仍待完成。真实产品 MCP 已后置，自动化测试的危险路径继续使用无云副作用 fixture，四宿主真实交互探测仍是发布门禁。

退出标准：

- Agent 只看到三个工具；
- 本地 OBS 与 KooCLI 映射能力可搜索和描述；
- 只有无风险普通 read 可直接执行；
- write/destructive/privileged/cost/sensitive-read 必须获得可信审批；
- 失败和结果未知不自动切换执行器；
- credential session 过期、撤销、重启和账号不匹配测试通过。

## M3：四宿主与首发能力

交付：

- Codex、Claude Code、OpenCode、华为云码道声明式模板；
- 四宿主固定审批签发器集成；
- Canonical Skills 及四宿主构建产物；
- 自动配置、验证和安全卸载；
- 首版本地 OBS capability 数据与后续产品 MCP 静态接入口；
- KooCLI 对未覆盖服务的固定能力映射；
- 3～5 个端到端场景。

退出标准：

- 四宿主完成相同的 Router/Skill 启动验证；
- 本地 OBS provider 完成真实最小权限账号资源操作；
- OBS 与已绑定 KooCLI 能力按最终首发清单通过；
- 创建、修改、删除、IAM、网络、计费和敏感读取覆盖可信审批门禁；
- 安装失败能够恢复宿主配置。

## M4：发布加固

交付：

- Windows amd64、Linux amd64/arm64、macOS amd64/arm64 测试；
- credentials 文件权限与泄漏扫描；
- 本地 OBS/KooCLI 凭证日志、argv、环境和磁盘扫描；
- approval receipt 篡改、重放、并发消费和 issuer 替换测试；
- KooCLI 命令注入、超时和结果未知测试；
- npm SBOM、许可证、漏洞、secret 和 provenance；
- 安装、凭证、危险操作、卸载和故障诊断文档；
- 首个开源版本发布候选。

退出标准：

- 技术架构首版验收基线全部通过；
- 公开仓库不包含凭证、内部 endpoint 或开发机路径；
- npm 安装包内容与源码发布标签一致；
- 本地 OBS 会话和 KooCLI argv invoker 的 AK/SK 边界通过最小权限真实账号验收。

## 测试矩阵

平台：

- Windows amd64；
- Linux amd64/arm64；
- macOS amd64/arm64。

宿主：

- OpenCode；

## 实施前外部输入

- 公共 npm scope 与发布身份；
- `auth set` 固定只读账号身份校验能力和责任人；
- 统一受信审批 companion 的四宿主进程/loopback 隔离验证和交互责任人；
- 首个 ECS KooCLI capability 的元数据可用性与最小权限账号验收；mapping、版本、SHA-256 与 argv invoker 已绑定；
- 3～5 个端到端验收场景。

## 不进入首版

- 真实 Streamable HTTP 产品 MCP；仅保留静态接入口和接入规范；
- 动态 Provider Registry、签名、吊销和远程 denylist；
- 第三方或社区 Provider；
- OS Keyring 和多账号 target；
- 独立凭证控制面、mTLS、信封加密和 KMS/HSM；
- 企业策略中心、集中审计和遥测；
- 独立 update/repair 和复杂 drift 检测；
- 离线、HTTP/HTTPS 代理和 headless Linux；
- 常驻本地 daemon；
- 任意代码工作流执行器；
- 全量 OpenAPI 在 Agent 侧展开为工具。
