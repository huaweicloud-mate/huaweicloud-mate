# 安全架构

状态：Proposed v0.3-lite
日期：2026-07-13

## 1. 安全目标

- AK/SK 不进入 Agent 上下文、Tool 参数、命令行、workspace 或日志；
- 只有随 npm 内置的官方产品 MCP 可以接收 AK/SK；
- 创建、修改、删除、IAM、网络、计费和敏感读取必须经过可信审批签发器确认；
- 副作用执行失败、超时或结果未知时不得自动更换执行器重试；
- KooCLI 和宿主配置变更必须可验证、可恢复且不覆盖用户未知内容。

## 2. 明确信任边界

```text
不可信：
  Agent 输出、Prompt、Workspace、Skill 外部内容、普通 Tool 参数

本地受信：
  本地 Router、内置 Provider 清单、KooCLI Adapter、Installer、固定审批签发器

受文件权限保护：
  用户级 credentials.json

远程受信：
  npm 内置的官方产品 MCP 及其 HTTPS 终止链路
```

首版明确接受以下取舍：

- AK/SK 以受文件权限保护的明文形式保存在用户目录；
- AK/SK 通过 HTTPS 离开本机；
- 官方产品 MCP 可以在进程内存中接触明文 AK/SK；
- 首版不提供 OS Keyring、设备 mTLS、应用层信封加密、KMS/HSM 或独立凭证控制面。

因此产品 MCP 和其 TLS 终止、日志、trace、故障转储链路都属于凭证信任边界。该方案不得扩展到第三方或用户自定义 MCP。

## 3. 主要威胁

- Prompt injection 诱导 Agent 泄露凭证或绕过确认；
- 恶意 workspace 修改 MCP 配置或 endpoint；
- 本地其他进程读取 credentials 文件；
- 官方产品 MCP、网关或日志系统保存 AK/SK；
- session ID 泄漏后被重放；
- KooCLI 参数拼接造成命令注入；
- MCP 与 KooCLI 自动切换造成重复副作用；
- npm、KooCLI 下载包或内置 Provider 配置被篡改；
- 安装或卸载覆盖用户已有配置。

## 4. 本地凭证文件

首版只支持一个当前账号。

凭证通过以下命令管理：

```text
hcloud-agent auth set
hcloud-agent auth status
hcloud-agent auth remove
```

约束：

- `auth set` 使用不回显的交互输入；
- 禁止 `--ak`、`--sk` 和环境变量回显；
- credentials 文件与普通配置文件分离；
- 每次 `auth set` 生成新的随机 `generation`，Core 在执行和复用 session 前重新检查；
- Linux/macOS 权限必须为 `0600`；
- Windows ACL 必须只允许当前用户；
- credentials 文件不得位于 workspace、项目目录或同步目录；
- `auth status` 只返回是否配置、更新时间和账号校验摘要；
- `auth set` 通过 M0 绑定的固定只读身份校验能力获得并保存非敏感 account/domain identity；
- `auth set/remove` 对当前进程已知 session 尽力立即撤销；
- 其他 Core 发现 `generation` 变化或文件删除后停止复用旧 session 并尽力撤销；
- 无共享控制面时不承诺全部 session 立即撤销，Provider 遗留 session 最迟在 900 秒 TTL 或实例重启时失效。

Installer 和 Router 启动时必须验证文件所有者与权限。权限过宽时拒绝云资源执行并给出修复指引。

## 5. 产品 MCP 凭证短会话

产品 MCP 在与数据面同源的 HTTPS endpoint 暴露 `POST /credential-sessions`。

Core 发送：

```json
{
  "protocol": "huaweicloud-credential-session/v1",
  "accessKey": "...",
  "secretKey": "...",
  "credentialGeneration": "uuid",
  "requestedTtlSeconds": 900
}
```

强制控制：

- 必须使用公开可信证书的 HTTPS；
- credential endpoint 与 MCP data plane 必须同源；
- 禁止 HTTP 降级、跨域重定向和用户自定义 endpoint；
- 请求与响应设置 `Cache-Control: no-store`；
- AK/SK 不得进入 access log、application log、trace、metric label、数据库、磁盘 cache 或 crash dump；
- Provider 仅在进程内存中保存，TTL 不超过 15 分钟；
- Provider 返回不透明、高熵、不可预测的 session ID 和 route token；
- session 绑定 provider instance 和已验证账号；
- 同源网关必须使用 route token 把数据面调用和撤销请求路由到创建 session 的实例；
- 过期、服务重启或显式撤销后 session 失效；凭证更新通过代次检查停止本地复用；
- Core 把 Provider 返回的账号身份与 `auth set` 已验证并绑定到当前 generation 的 identity 比较。

数据面调用只携带 session ID 和 route token，不再携带 AK/SK。两者不得进入 Agent 上下文或普通日志，日志最多保留不可逆摘要。

## 6. Router 风险门禁

复合风险模型：

| 字段 | 值 | 默认处理 |
|---|---|---|
| `operationKind` | `read` | 仅在无风险标签且明确无需确认时直接执行 |
| `operationKind` | `write` | 始终要求可信审批 |
| `riskTags` | `destructive` | 展示不可逆影响并要求可信审批 |
| `riskTags` | `privileged` | 展示 IAM、权限或网络暴露范围并要求可信审批 |
| `riskTags` | `cost` | 展示计费资源与规格并要求可信审批 |
| `riskTags` | `sensitive-read` | 展示敏感数据范围并要求可信审批 |

首次 execute 生成进程内 `previewId` 和 challenge；受信签发器在明确用户操作后生成 `approvalReceipt`。receipt 必须：

- 绑定 preview、challenge、canonical 参数摘要、executor、凭证代次、账号摘要、region/project 和过期时间；
- 由安装时固定的 issuer 使用受保护密钥或宿主可验证机制签发；
- 不允许 Agent、Prompt、Skill 或普通 Tool 参数自行签发；
- Router 在 dispatch 前原子消费，失败、超时和 `OUTCOME_UNKNOWN` 后仍保持 consumed；
- 任一绑定字段变化、进程重启、重放或过期时失效；
- 不包含 AK/SK、session ID、route token 或完整敏感参数。

v1 摘要使用 RFC 8785 JCS + SHA-256；receipt 签名覆盖除 `signature` 外的全部字段，有效期最长 300 秒，本地允许时钟偏差最长 30 秒。

首版不建设通用 Policy Engine 或企业策略中心。风险规则是 Router 的固定代码和内置 capability 元数据。

## 7. 执行器安全

- Tool 参数中的执行器选择只视为不可信偏好，Router 仍校验 capability、健康和固定规则；
- 默认在执行前选择健康且支持能力的产品 MCP，否则选择 KooCLI；
- 生成 preview 后锁定 executor；
- 失败、超时或 `OUTCOME_UNKNOWN` 不自动切换；
- 只有明确幂等且结果确定的读操作允许受控重试；
- 需要切换执行器时必须重新预览和确认。

## 8. KooCLI 安全

- 预装 KooCLI 只有在版本兼容且 doctor 通过时复用；
- 私有版本只从批准的官方 HTTPS 地址下载固定版本；
- 校验 SHA-256 后才激活；
- 使用绝对路径和参数数组，禁止 Shell 拼接；
- AK/SK 通过子进程环境注入，不放入命令行；
- 子进程继承最小环境并设置超时、取消和输出上限；
- 不修改系统 KooCLI，不加入 PATH，不在运行期跟随 `latest`。

## 9. 输出与日志

所有结果进入 Agent 上下文前必须：

- 进行结构和大小检查；
- 清理 AK/SK、session ID、Authorization、签名、token 和私钥；
- 按 capability 的 output schema 校验，并按 JSON Pointer 脱敏敏感字段；
- 拒绝未知结构、超出大小上限或不允许的 Provider 自然语言；
- 确认摘要只使用静态 capability 和已校验参数生成；
- 对错误堆栈进行规范化。

本地 JSONL 日志只记录脱敏摘要、request ID、executor、风险、确认结果、耗时和错误分类。首版不上传遥测。

## 10. 安装与供应链

### npm

- 公共 npm 发布构建产物、许可证清单和 SBOM；
- 依赖锁定并执行漏洞、恶意包和 secret 扫描；
- 不通过 `postinstall` 修改宿主；
- `npx` 只作为安装入口，四宿主长期配置只能指向固定用户目录下的稳定 launcher；
- Provider endpoint 和 capability 数据属于代码审查范围。

### KooCLI

- 固定版本和 SHA-256 清单随插件发版；
- 安装后运行最小只读 smoke test；
- 验证失败不得标记安装成功。

### 宿主配置

- 修改前备份；
- 备份文件仅当前用户可读并有明确保留期；
- 原子写入，回滚前比较配置 hash，发现并发用户修改时停止并报告；
- 只删除 install-state 证明由插件创建的内容；
- 同名冲突停止安装，不静默覆盖。

## 11. 首版不覆盖

- 凭证静态加密或硬件保护；
- 企业策略下发和集中审计；
- 第三方 Provider；
- 离线、代理和 headless Linux；
- 多账号隔离；
- 远程 Provider 紧急吊销；
- 被攻陷官方产品 MCP 后的凭证保密性。

最后一项是本方案最重要的剩余风险：一旦官方产品 MCP 或其可信网关被攻陷，攻击者可能获取活跃 session 中的 AK/SK。首版通过短 TTL、禁止持久化和凭证轮换降低暴露窗口，但不能消除此风险。

## 12. 发布门槛

- credentials 文件权限测试覆盖所有支持平台；
- AK/SK 泄漏扫描覆盖进程参数、日志、trace、错误和工作区；
- credential session 过期、撤销、重启和账号不匹配测试通过；
- route token 多实例路由、credentials generation 变化和最长 900 秒遗留窗口测试通过；
- Provider contract/capability/tool schema digest 失配时 fail closed；
- preview/approval receipt 的篡改、并发消费、重放、过期和 issuer 替换测试通过；
- 复合风险、敏感读取、输出 schema、JSON Pointer 脱敏和大小上限测试通过；
- KooCLI 命令注入和结果未知测试通过；
- 四宿主配置备份、回滚和卸载测试通过；
- 至少一个内置产品 MCP 完成端到端安全测试。
