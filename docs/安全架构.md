# 安全架构

状态：Proposed v0.3-lite
日期：2026-07-13

## 1. 安全目标

- AK/SK 不进入 Agent 上下文、Tool 参数、workspace 或插件日志；唯一命令行例外是 ADR-0050 经用户明确授权的直接 KooCLI 子进程 argv；
- 首版只有内置本地 OBS provider 可以接收 AK/SK；后续只有随 npm 静态内置的官方产品 MCP 可以新增该权限；
- 创建、修改、删除、IAM、网络、计费和敏感读取必须经过可信审批签发器确认；
- 副作用执行失败、超时或结果未知时不得自动更换执行器重试；
- KooCLI 和宿主配置变更必须可验证、可恢复且不覆盖用户未知内容。

## 2. 明确信任边界

```text
不可信：
  Agent 输出、Prompt、Workspace、Skill 外部内容、普通 Tool 参数

本地受信：
  本地 Router、内置 Provider 清单、KooCLI Adapter、Installer、固定审批签发器

受文件权限保护：
  用户级 credentials.json

远程受信：
  后续 npm 内置的官方产品 MCP 及其 HTTPS 终止链路
```

首版明确接受以下取舍：

- AK/SK 以受文件权限保护的明文形式保存在用户目录；
- AK/SK 通过 HTTPS 离开本机；
- 首版本地 OBS provider 可以在进程内存中接触明文 AK/SK；后续官方产品 MCP 仅能在受审查的同域短会话中接触；
- 首版不提供 OS Keyring、设备 mTLS、应用层信封加密、KMS/HSM 或独立凭证控制面。

真实产品 MCP 已后置；接入后其 TLS 终止、日志、trace、故障转储链路都属于凭证信任边界。该方案不得扩展到第三方或用户自定义 MCP。

## 3. 主要威胁

- Prompt injection 诱导 Agent 泄露凭证或绕过确认；
- 恶意 workspace 修改 MCP 配置或 endpoint；
- 本地其他进程读取 credentials 文件；
- 官方产品 MCP、网关或日志系统保存 AK/SK；
- session ID 泄漏后被重放；
- KooCLI 参数拼接造成命令注入；
- MCP 与 KooCLI 自动切换造成重复副作用；
- npm、KooCLI 下载包或内置 Provider 配置被篡改；
- 安装或卸载覆盖用户已有配置。

## 4. 本地凭证文件

首版只支持一个当前账号。

凭证通过以下命令管理：

```text
huaweicloud-mate auth set
huaweicloud-mate auth status
huaweicloud-mate auth remove
```

约束：

- `auth set` 使用不回显的交互输入；
- 首版只接受一组永久 AK/SK，不请求密码、SecurityToken、SSO、profile 名或其他认证材料；
- 禁止 `--ak`、`--sk` 和环境变量回显；
- credentials 文件与普通配置文件分离；
- 每次 `auth set` 生成新的随机 `generation`，Core 在执行和复用 session 前重新检查；
- Linux/macOS 权限必须为 `0600`；
- Windows ACL 必须只允许当前用户；
- credentials 文件不得位于 workspace、项目目录或同步目录；
- `auth status` 只返回是否配置、更新时间和账号校验摘要；
- `auth set` 通过 M0 绑定的固定只读身份校验能力获得并保存非敏感 account/domain identity；
- `auth set/remove` 对当前进程已知 session 尽力立即撤销；
- 其他 Core 发现 `generation` 变化或文件删除后停止复用旧 session 并尽力撤销；
- 无共享控制面时不承诺全部 session 立即撤销，Provider 遗留 session 最迟在 900 秒 TTL 或实例重启时失效。

Installer 和 Router 启动时必须验证文件所有者与权限。权限过宽时拒绝云资源执行并给出修复指引。

当前实现把 `credentials.json` 放在 `hcloud-agent` 用户数据目录、运行时目录之外。写入使用临时文件、`0600`/当前用户 ACL、摘要比较和原子提交；读取拒绝 symlink、非普通文件、超限、未知字段和权限异常。Windows 每次读取前通过固定参数的系统 ACL 工具重新收紧为当前用户，POSIX 校验 owner 和组/其他用户权限。`auth set` 的固定校验能力暂由内置本地 OBS provider 执行 `ListBuckets`，从响应 Owner ID 绑定 account/domain identity；该账号需有 `obs:bucket:ListAllMyBuckets`，以后真实产品 MCP 到位时替换 verifier，不改变凭证文件或 Router identity 契约。

Region、project ID、domain/account ID 属于 scope 或身份校验结果，不扩展 credentials 的秘密字段。credentials v1 只允许 `accessKey` 与 `secretKey`；`securityToken`、密码、profile 等未知字段一律拒绝。Windows `7.2.12` 实测确认覆盖 HOME/USERPROFILE 不能把 `~/.hcloud` 重定向到插件目录，因此不创建或覆盖 profile。经用户明确授权，ADR-0050 允许受信 invoker 在 KooCLI 子进程 argv 中使用永久 AK/SK；插件不能消除同账号进程、管理员或 EDR 对该命令行的可见性。

## 5. 首版本地会话与后续产品 MCP 短会话

首版内置本地 OBS provider 以 generation、账号绑定、随机 session ID、随机 route token、provider instance 和最长 900 秒 TTL 维护进程内短会话。它实现 `ListBuckets`、有界文本对象读取、创建私有桶和删除空桶，endpoint 由代码固定生成，直接按 OBS 官方签名协议发送请求；AK/SK 不进入 Tool schema、日志或响应。文本对象读取属于 `read + sensitive-read`，仅允许明确 MIME、fatal UTF-8、无内容编码且最多 64 KiB；创建桶属于 `write + privileged + cost`，删除空桶属于 `write + destructive + privileged`，三者必须通过受信 companion 点击审批。对象正文仍经过 ADR-0036 的 credential-like 输出门禁；创建、删除请求发出后的网络中断统一返回 `OUTCOME_UNKNOWN` 且不自动重试。它不冒充 Streamable HTTP 产品 MCP，后续真实产品 MCP 仍通过下述保留接口接入。

产品 MCP 在与数据面同源的 HTTPS endpoint 暴露 `POST /credential-sessions`。

Core 发送：

```json
{
  "protocol": "huaweicloud-credential-session/v1",
  "accessKey": "...",
  "secretKey": "...",
  "credentialGeneration": "uuid",
  "requestedTtlSeconds": 900
}
```

强制控制：

- 必须使用公开可信证书的 HTTPS；
- credential endpoint 与 MCP data plane 必须同源；
- 禁止 HTTP 降级、跨域重定向和用户自定义 endpoint；
- 请求与响应设置 `Cache-Control: no-store`；
- AK/SK 不得进入 access log、application log、trace、metric label、数据库、磁盘 cache 或 crash dump；
- Provider 仅在进程内存中保存，TTL 不超过 15 分钟；
- Provider 返回不透明、高熵、不可预测的 session ID 和 route token；
- session 绑定 provider instance 和已验证账号；
- 同源网关必须使用 route token 把数据面调用和撤销请求路由到创建 session 的实例；
- 过期、服务重启或显式撤销后 session 失效；凭证更新通过代次检查停止本地复用；
- Core 把 Provider 返回的账号身份与 `auth set` 已验证并绑定到当前 generation 的 identity 比较。

数据面调用只携带 session ID 和 route token，不再携带 AK/SK。两者不得进入 Agent 上下文或普通日志，日志最多保留不可逆摘要。

## 6. Router 风险门禁

复合风险模型：

| 字段 | 值 | 默认处理 |
|---|---|---|
| `operationKind` | `read` | 仅在无风险标签且明确无需确认时直接执行 |
| `operationKind` | `write` | 始终要求可信审批 |
| `riskTags` | `destructive` | 展示不可逆影响并要求可信审批 |
| `riskTags` | `privileged` | 展示 IAM、权限或网络暴露范围并要求可信审批 |
| `riskTags` | `cost` | 展示计费资源与规格并要求可信审批 |
| `riskTags` | `sensitive-read` | 展示敏感数据范围并要求可信审批 |

首次 execute 生成进程内 `previewId` 和 challenge；受信签发器在明确用户操作后生成 `approvalReceipt`。receipt 必须：

- 绑定 preview、challenge、canonical 参数摘要、executor、凭证代次、账号摘要、region/project 和过期时间；
- 由 Router 通过固定 launcher 和私有管道启动的一次性 companion 使用内存临时密钥签发；
- 不允许 Agent、Prompt、Skill 或普通 Tool 参数自行签发；
- Router 在 dispatch 前原子消费，失败、超时和 `OUTCOME_UNKNOWN` 后仍保持 consumed；
- 任一绑定字段变化、进程重启、重放或过期时失效；
- 不包含 AK/SK、session ID、route token 或完整敏感参数。

四宿主统一使用 npm 内置的 `huaweicloud-mate.local-approval` companion。Router 为每个待审批 preview 通过固定绝对路径启动一次性进程，并通过不暴露给 Agent 的继承管道接收临时公钥；receipt 同时绑定该随机 `approvalSessionId`。私钥只存在于 companion 内存，批准或拒绝后随进程退出销毁，不写磁盘、不要求密码，也不使用 OS Keyring。companion 不作为普通 Tool 或 MCP tool 暴露，并禁止任何自动批准或非交互签发路径。宿主原生审批 UI 只可作为额外提示，不是 v1-lite receipt 的信任来源。

开发态 companion launcher 已实现构建时完整 runtime artifact manifest，并在启动前逐项校验审批模块、契约注册表和 schema 的 SHA-256 及非 symlink 普通文件属性；同时使用空 argv/`execArgv`、最小环境和 Node 私有父子 IPC。独立审批页只监听随机 loopback 端口和 256 位随机路径，要求精确 Host、同源 Origin 和 CSRF，设置 no-store、CSP、no-referrer 和 frame deny；展示值同时经过终端控制字符转义与 HTML 转义。

最小 Router 核心默认从固定 runtime manifest 创建 launcher。首次危险 `execute` 在内存生成并锁定 preview；第二次调用只额外提交 `previewId`，由不作为 MCP Tool 暴露的受信内部 review 路径启动 companion，并把 launcher 已验签的原始 receipt 绑定到该 preview。Router 在内部重新校验 capability、canonical 参数摘要、scope、executor、credentials generation、账号、receipt 时效和精确内容，并在第一个 dispatch `await` 前同步转换为 `consumed`；receipt 不进入 Agent 上下文。同一 preview 的并发调用共享一次 review，只有一个调用可以 dispatch；拒绝或身份变化会消费 preview，执行失败和 `OUTCOME_UNKNOWN` 也不会恢复。`doctor --approval-probe` 使用随机本地 challenge 验证同一链路，不读取 credentials、不访问云资源，也不要求密码。

这些 Web/IPC 防护主要阻止跨站请求、普通端口探测和意外数据泄漏，不构成同账号任意代码执行下的用户在场证明。内存临时密钥消除了磁盘私钥读取和密码解锁问题，但同账号进程仍可能尝试枚举浏览器 URL、自动提交 loopback 表单、调试或注入 companion。四宿主集成必须验证 Agent sandbox 无法访问私有 IPC、进程信息和审批 loopback；同时验证 runtime manifest/安装目录不可替换及进程禁止调试/转储。无法满足时对应宿主不得宣称强制审批。该门禁不恢复独立凭证控制面。

Router 已实现 capability `sensitivePaths` 的 JSON Pointer 脱敏：执行器原始结果先通过 output schema、序列化和原始大小限制，再克隆为纯 JSON，并只对 own-property 和合法数组索引写入固定 `[REDACTED]` 标记；支持 `~0`、`~1` 转义，不修改执行器原对象，也不允许 `__proto__` 或数组 `length` 造成原型/结构写入。ADR-0036 又在脱敏后扫描明确的凭证字段、Authorization/安全令牌、签名 URL、SDK/OBS 授权串和 PEM 私钥标记；未声明或未完整脱敏的匹配项返回不含路径和值的 `OUTPUT_REJECTED`。扫描不猜测普通高熵字符串，因此正式 capability 的 output schema 与敏感路径审查仍是发布门禁。

开发态 stdio MCP Server 只注册 search、describe、execute，未知异常统一归一为不含堆栈的 `UNKNOWN`。reference catalog/executor 不读取 credentials、不访问网络，只用于协议测试。危险两阶段流程已按 ADR-0010 冻结：公开 schema 拒绝 Agent 提交 receipt，Router 在第二次调用内部完成交互审批和验签。仍禁止自动批准、隐藏批准、第四个 Tool 或 Agent 可调用的签发入口。

v1 摘要使用 RFC 8785 JCS + SHA-256；receipt 签名覆盖除 `signature` 外的全部字段，有效期最长 300 秒，本地允许时钟偏差最长 30 秒。

首版不建设通用 Policy Engine 或企业策略中心。风险规则是 Router 的固定代码和内置 capability 元数据。

## 7. 执行器安全

- Tool 参数中的执行器选择只视为不可信偏好，Router 仍校验 capability、健康和固定规则；
- 默认在执行前选择健康且支持能力的产品 MCP，否则选择 KooCLI；
- 生成 preview 后锁定 executor；
- 失败、超时或 `OUTCOME_UNKNOWN` 不自动切换；
- 只有明确幂等且结果确定的读操作允许受控重试；
- 需要切换执行器时必须重新预览和确认。

## 8. KooCLI 安全

- 预装 KooCLI 只有在版本兼容且 doctor 通过时复用；
- 私有版本只从批准的官方 HTTPS 地址下载固定版本；
- 只接受 ADR-0048 固定的官方 host 与五个精确 `/cli/latest/` 对象，拒绝重定向、查询参数和其他路径，校验内置 SHA-256 后才解包与激活；上游对象变化必须摘要失配；
- ZIP/`tar.gz` 解包限制大小并拒绝路径穿越、链接、未知条目和多个可执行入口；
- 使用 staging、原子目录提交、安装记录与可执行文件 hash 复核；
- 使用绝对路径和参数数组，禁止 Shell 拼接；
- KooCLI 不使用持久 profile、普通凭据环境变量或 shell；AK/SK 仅按 ADR-0050 进入直接 `hcloud` 子进程 argv，并接受其进程列表可见风险；
- 子进程继承最小环境并设置超时、取消和输出上限；
- 不修改系统 KooCLI，不加入 PATH；`latest` 只是摘要绑定的下载位置，运行期不会接受新字节或自动更新。

## 9. 输出与日志

所有结果进入 Agent 上下文前必须：

- 进行结构和大小检查；
- 清理 AK/SK、session ID、Authorization、签名、token 和私钥；
- 按 capability 的 output schema 校验，并按 JSON Pointer 脱敏敏感字段；
- 拒绝未知结构、超出大小上限或不允许的 Provider 自然语言；
- 确认摘要只使用静态 capability 和已校验参数生成；
- 对错误堆栈进行规范化。

真实 stdio Router 将本地 JSONL 写入固定用户数据目录，只记录归一化 Agent、插件版本、correlation/request ID、capability、executor、scope、风险、确认结果、参数/结果 SHA-256 摘要、耗时和错误分类。日志拒绝 symlink/非普通文件，使用当前用户权限并有界轮转；不记录参数/结果正文、账号、generation、session、route token、回执或异常文本。dispatch 前日志不可用时停止执行，dispatch 后日志失败不把已知结果改写为可重试失败。首版不上传遥测。

## 10. 安装与供应链

### npm

- 公共 npm 发布构建产物、许可证清单和 SBOM；
- 依赖锁定并执行漏洞、恶意包和 secret 扫描；
- 不通过 `postinstall` 修改宿主；
- `npx` 只作为安装入口，四宿主长期配置只能指向固定用户目录下的稳定 launcher；
- 构建时生成自包含运行入口和完整安装清单；候选版本在 staging 复制后复验，稳定 launcher 每次启动前校验 active pointer、非 symlink 普通文件、大小和 SHA-256；
- 正式 CLI 已在安装前、卸载读取状态前执行用户级 runtime 递归权限门禁：POSIX 要求当前 owner 且目录 `0700`/文件 `0600`，Windows 递归移除继承并仅授予当前 SID；它覆盖 launcher、pointer、版本、状态、恢复/备份证据和私有 KooCLI；
- ADR-0037 已关闭主 CLI 在摘要校验后按路径二次读取的窗口；ADR-0038 又让正式 companion 入口经私有 stdin 从已验签内存字节加载，bootstrap 不含批准或签名逻辑。ADR-0039 将同轮验签的七份契约文本也放入私有 envelope，父端 verifier 与子端 signer 不再按路径重读 schema。ADR-0041 再禁用 SIGUSR1 inspector、拒绝 Node 注入/转储环境，并把随机 loopback 页面收敛为一次读取、严格 Host/Origin/CSRF/字段及时限。完整摘要和目录 ACL 仍不能抵抗同账号任意写入同时替换 launcher、pointer、manifest 和全部制品；浏览器启动参数中的一次性 URL、私有句柄及 OS 级调试仍需 provenance 和四宿主真实隔离；
- Provider endpoint 和 capability 数据属于代码审查范围。

### KooCLI

- 固定版本和 SHA-256 清单随插件发版；
- 安装后运行最小只读 smoke test；
- 验证失败不得标记安装成功。

### 宿主配置

OpenCode/码道跨版本升级不重新生成用户配置，也不替换初装时保存的 rollback backup。候选配置必须与受管 stable launcher 条目完全一致；Skill 只在 ownership/hash 可证明时替换。强制终止恢复只收敛旧/候选两个已知 tree hash，未知 quarantine 内容保留并 fail closed。

- 修改前备份；
- 备份文件仅当前用户可读并有明确保留期；
- 原子写入，回滚前比较配置 hash，发现并发用户修改时停止并报告；
- 只删除 install-state 证明由插件创建的内容；
- 同名冲突停止安装，不静默覆盖。

## 11. 首版不覆盖

- 凭证静态加密或硬件保护；
- 企业策略下发和集中审计；
- 第三方 Provider；
- 离线、代理和 headless Linux；
- 多账号隔离；
- 远程 Provider 紧急吊销；
- 后续接入的官方产品 MCP 被攻陷后的凭证保密性。

最后一项是后续产品 MCP 接入时必须重新验收的剩余风险：一旦官方产品 MCP 或其可信网关被攻陷，攻击者可能获取活跃 session 中的 AK/SK。短 TTL、禁止持久化和凭证轮换只能降低暴露窗口，不能消除此风险。

## 12. 发布门槛

- credentials 文件权限测试覆盖所有支持平台；
- AK/SK 泄漏扫描覆盖进程参数、日志、trace、错误和工作区；
- credential session 过期、撤销、重启和账号不匹配测试通过；
- route token 多实例路由、credentials generation 变化和最长 900 秒遗留窗口测试通过；
- Provider contract/capability/tool schema digest 失配时 fail closed；
- preview/approval receipt 的篡改、并发消费、重放、过期和 issuer 替换测试通过；
- 复合风险、敏感读取、输出 schema、JSON Pointer 脱敏和大小上限测试通过；
