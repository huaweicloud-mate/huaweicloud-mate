# 安全架构

状态：Proposed v1

## 1. 保护目标

- 用户永久 AK/SK；
- 产品 MCP credential session；
- 本地 target/account/project/region；
- Provider Registry 信任根、manifest 与吊销信息；
- KooCLI 二进制和插件 npm 供应链；
- 高风险云资源操作的授权与审计证据。

## 2. 主要威胁

- Prompt injection 诱导 Agent 泄露凭证或绕开确认；
- 恶意 workspace 修改 Agent/MCP 配置指向伪造 endpoint；
- 恶意或被攻陷的产品 MCP 持久化 AK/SK；
- 公网中间人、TLS 终止层或日志系统获取凭证；
- npm/KooCLI/Registry 供应链篡改；
- MCP 与 KooCLI 失败切换造成重复副作用；
- 工具输出携带敏感资源数据进入上下文或日志；
- Adapter 卸载或修复误删用户配置。

## 3. 信任边界

```text
不可信：Agent 输出、Prompt、Workspace、普通工具参数、任意外部 MCP
受限可信：本地 Adapter、Skills、KooCLI 子进程
高可信：本地 Core、OS Secret Store、签名 Registry
经审核可信：华为云产品 MCP 数据面与凭证控制面
```

第三方 MCP 永远不能使用 AK/SK 委托协议。

## 4. 本地凭证

- `target add` 使用不回显的交互式输入；
- 禁止 `--ak`、`--sk` 命令行参数；
- Windows Credential Manager、macOS Keychain、Linux Secret Service/libsecret 保存凭证；
- 首版不支持没有桌面 Keyring 的 headless Linux，不提供明文 fallback；
- Core 配置只保存 opaque credential reference；
- Secret Store 读取只发生在 KooCLI 子进程注入或 Provider 会话建立前；
- target 删除和凭证轮换必须撤销全部关联远程 session。

## 5. 公网 Provider 凭证委托

选定方案：永久 AK/SK 短期内存委托。

纵深控制：

1. 公网 TLS；
2. 本地设备短期 mTLS 客户端身份；
3. Registry 固定 endpoint、Provider 身份和 credential encryption public key；
4. AK/SK payload 使用 AEAD 信封加密；
5. nonce、timestamp、correlation ID 和 replay cache；
6. session TTL 不超过 15 分钟；
7. Provider 内存专用 session store，禁止持久化；
8. session 与 MCP connection、device、provider、account 绑定；
9. 账号身份回证和 Core 二次校验；
10. 撤销、断连、重启、过期时清理。

### 5.1 mTLS 身份引导

Core 首次配置 target 时生成设备密钥对。建议通过华为云 API Gateway/IAM 鉴权的注册接口提交设备公钥：请求由本地 AK/SK 签名，SK 本身不在注册请求中传输。平台验证用户身份后签发短期客户端证书或等价设备凭证。

证书私钥存入 OS Secret Store/平台密钥设施；证书短期轮换。共享证书、npm 包内置私钥或长期静态客户端密钥均被禁止。

### 5.2 应用层信封加密

Registry 为每个 Provider 发布受签名保护的公钥和 key ID。Core 使用随机数据密钥加密 AK/SK payload，再用 Provider 公钥加密数据密钥。Provider 私钥必须由受控 KMS/HSM 或等价设施托管。

该层保证在反向代理或 API gateway 终止 TLS 时，凭证明文仍只对目标 Provider 可见。

## 6. Policy Engine

Policy 输入：

```text
agent + adapter + target + account + project + region
+ capability + executor + risk + parametersDigest + providerHealth
```

Policy 输出：

```text
allow | confirmation-required | deny
```

- read 默认允许；敏感输出可要求额外确认或脱敏；
- write 生成短期 plan；
- destructive、privileged、cost 每次确认；
- 企业/内置 deny 高于 Skill 和 Agent 指令；
- plan token 绑定参数摘要、executor、target、作用域、过期时间和 nonce；
- 任何字段变化都使 plan 失效。

## 7. 双执行器安全

- MCP 与 KooCLI 共享相同 Policy Engine；
- 低风险 read 可以 `auto` 选择并记录 executor；
- 副作用动作在 plan 阶段固定 executor；
- 超时或不确定结果必须返回 `OUTCOME_UNKNOWN`，禁止自动换执行器；
- 重试只允许由 executor contract 明确证明幂等的操作；
- KooCLI 使用参数数组启动，禁止 Shell 拼接；
- 原生 `hcloud` 不加入 PATH。

## 8. 输出与日志脱敏

统一 redaction 层至少识别：

- AK/SK/SecurityToken；
- `Authorization`、`X-Auth-Token`、`X-Security-Token`；
- URL query 中的 token/signature；
- PEM/JWK 私钥；
- KooCLI profile 和完整签名请求；
- Provider session ID（日志中只保留不可逆摘要）。

执行结果在进入 Agent 上下文前先经过大小限制、结构验证和敏感字段策略。审计只记录脱敏摘要与 request ID。

## 9. 供应链

### 9.1 npm

- 公共 npm 只发布构建产物和 SBOM；
- CI 使用锁定依赖、可复现构建和发布身份证明；
- 禁止依赖安装期间的隐式远程脚本修改宿主；
- Installer 的所有变更由显式命令触发；
- 发布前执行恶意包、许可证、漏洞和 secret 扫描。

### 9.2 KooCLI

- 只从批准的官方 HTTPS 地址下载固定版本；
- 校验官方 SHA-256 和内部 release manifest；
- staging 后健康检查，再原子切换；
- 保留上一个已验证版本用于回滚；
- 不在运行期静默跟随 `latest`。

### 9.3 Registry

- Manifest 由插件平台团队签名；
- signing key 由 KMS/HSM 或等价系统托管；
- 支持 key rotation、expiry、revocation 和 last-known-good；
- workspace、Skill、Agent 不能增加信任根。

## 10. 环境边界

首版明确不支持：

- 无互联网/离线环境；
- HTTP/HTTPS 代理；
- 无桌面 Keyring 的 headless Linux。

`doctor` 必须在安装阶段检测这些条件并给出明确错误，不能降低安全要求继续安装。

## 11. 安全上线门槛

- Threat model 评审；
- 原始 AK/SK 委托专项安全审批；
- Provider conformance 全部通过；
- npm、KooCLI、Registry SBOM/签名/回滚演练；
- 四平台凭证泄漏扫描；
- Prompt injection 与高风险确认红队测试；
- Provider 被攻陷、证书泄漏、Registry key 泄漏和结果未知的应急演练。

任何远程 Provider 未通过门槛时只能 discovery-only；KooCLI 可继续作为本地受控执行器。
