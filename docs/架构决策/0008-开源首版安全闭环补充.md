# ADR-0008：开源首版安全闭环补充

- 状态：Accepted
- 日期：2026-07-13

## 背景

ADR-0007 将首版收敛为单一 npm package、三个 Router tools、静态内置 Provider、产品 MCP 优先、KooCLI 补位和最小风险门禁。阶段 5 评审后确认，该方向无需恢复 Proposed v0.2 的动态 Registry、独立凭证控制面、mTLS、信封加密、通用 Adapter SPI 或 Policy Engine，但以下边界必须在 M0 补齐：

- Agent、Prompt 和普通 Tool 参数属于不可信输入，Agent 自己回传 token 不能证明用户已经确认；
- 每个 Agent session 使用独立 Core 进程，无法保证 `auth set/remove` 立即撤销其他进程创建的全部远程 session；
- Provider session 只存于实例内存时，需要显式的多实例路由契约；
- 单值 `risk` 无法表达创建公网计费资源等复合风险，也无法安全处理敏感读取；
- `npx ... install` 的临时缓存位置不能作为宿主长期启动 Router 的路径；
- 静态 capability 与远端 Provider 版本必须在运行时 fail closed；
- 一次性确认、输出脱敏和安装回滚需要可测试的确定语义。

## 决策

### 1. 可信审批凭据

首个危险操作 `execute` 调用只生成进程内 `previewId`、规范化参数摘要、确认摘要和审批 challenge。第二次调用必须携带受信任审批签发器生成的 `approvalReceipt`。

`approvalReceipt` 必须：

- 由 npm 内置且安装时绑定的固定审批签发器产生；
- 证明发生了明确的用户审批事件，不能由 Agent、Prompt、Skill 或普通 Tool 参数自行签发；
- 绑定 `previewId`、challenge、参数摘要、executor、账号凭证代次、region/project、批准时间和过期时间；
- 使用本地受保护密钥或宿主可验证机制进行完整性保护；
- 单次使用，Router 在 dispatch 前原子消费；
- 进程重启、参数变化、executor 变化、凭证代次变化或过期后失效。

v1 使用 RFC 8785 JSON Canonicalization Scheme（JCS）生成签名载荷，摘要算法固定为 SHA-256。receipt 签名覆盖除 `signature` 本身以外的全部字段，有效期不得超过 300 秒，允许的本地时钟偏差不得超过 30 秒。

四宿主仍采用固定声明式模板，不建设通用 Adapter SPI。M0 退出前必须为每个宿主绑定可验证的审批签发方式；若某宿主无法提供可信审批渠道，则不得声称其危险操作确认构成强制安全边界。

### 2. session 撤销与凭证代次

首版不增加全局 session 控制面。`credentials.json` 增加随机、非敏感的 `generation`。Core 在每次执行和复用 session 前重新检查当前凭证代次。

`auth set` 必须通过 M0 绑定的固定只读身份校验能力获得 account/domain identity，并把该非敏感 identity 与 generation 一起原子保存。产品 MCP 返回的 session 和执行身份必须与该基线一致。

`auth set/remove` 的保证调整为：

- 当前调用进程已知的 session 尽力立即撤销；
- 其他 Core 进程发现凭证代次变化或文件删除后，必须停止复用旧 session 并尽力撤销；
- Provider 侧遗留 session 最迟在 900 秒 TTL 到期或实例重启时失效；
- 文档不再承诺无共享控制面的“全部 session 立即撤销”。

### 3. Provider 实例路由

credential session 响应除 `sessionId` 外必须返回不透明 `routeToken`。后续数据面调用和单 session 撤销必须携带该 token，由同源网关路由到创建 session 的 Provider 实例。

`sessionId` 和 `routeToken` 都属于敏感运行时元数据，不进入 Tool schema、Agent 上下文或普通日志。Provider 不得依赖随机负载均衡碰巧命中原实例。

### 4. 复合风险模型

Capability 将单值 `risk` 拆为：

- `operationKind`：`read` 或 `write`；
- `riskTags`：可组合的 `destructive`、`privileged`、`cost`、`sensitive-read`；
- `confirmationRequired`：由固定规则和元数据共同确定。

只有不含风险标签且明确标记为无需确认的普通 read 可以直接执行。所有 write、所有风险标签、未知或不完整风险元数据均不得绕过确认。

### 5. 稳定运行路径

`npx @huaweicloud/agent-plugin install` 只作为安装入口。Installer 必须把运行时物化到固定用户目录的版本化子目录，并通过原子 `current` 指针或稳定 launcher 切换版本。四宿主配置不得引用 npm 临时 cache，也不得在 Agent session 运行期执行 `npx -y`。

### 6. Provider 兼容握手

Provider descriptor 固定期望的 Provider contract、credential session protocol、Provider 版本范围和 capability digest。健康或初始化响应必须返回实际值。任一值不兼容时 Router fail closed，不执行云资源操作。

### 7. 输出约束

Capability 必须声明结构化输出 schema、敏感字段 JSON Pointer、输出大小上限和是否允许 Provider 文本。确认摘要只能由 Router 使用静态 capability 与已校验参数生成，不能直接使用 Provider 返回的自然语言。

### 8. 一次性消费与结果未知

Router 使用 RFC 8785 JCS + SHA-256 计算参数、账号和 scope 摘要。`previewId` 在进程内维护 `pending -> consumed` 状态，dispatch 前原子消费。执行超时、失败或 `OUTCOME_UNKNOWN` 后不得复用 preview、receipt 或自动切换 executor。

## 保持不变

- Agent 仍只看到 search、describe、execute 三个 Router tools；
- 产品 MCP 和 capability 元数据仍随 npm 静态内置；
- 默认产品 MCP 优先，执行前不可用时选择 KooCLI；
- executor 在预览生成或执行开始后锁定；
- 首版仍为单账号、权限受限 credentials 文件、最长 15 分钟远程内存 session；
- 不恢复动态 Registry、第三方 Provider、独立凭证控制面、mTLS、信封加密、KMS/HSM、通用 Adapter SPI、Policy Engine、集中审计或复杂 drift 框架。

## 影响

- M0 必须产出 Approval Receipt、Capability、Provider、credential session、宿主模板和安装路径的可验证契约；
- 四宿主可信审批方式成为 M0 退出条件，而不是留到 M3 才验证；
- `auth set/remove` 的安全承诺与无 daemon、无共享控制面的实际能力一致；
- schema 在 M0 冻结前允许不兼容修订，冻结后按显式版本演进；
- ADR-0007 继续有效，本 ADR 仅补充其安全闭环。
