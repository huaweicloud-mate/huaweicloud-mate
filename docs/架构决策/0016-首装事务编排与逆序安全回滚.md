# ADR-0016：首装事务编排与逆序安全回滚

状态：Accepted
日期：2026-07-14

## 背景

ADR-0013、0014 和 0015 已分别提供宿主配置、宿主资产和 install-state 的有限事务。它们尚未规定跨组件提交顺序：若后续宿主失败或提交前验证失败，前面已经完成的修改必须安全撤回；install-state 又只能在所有宿主均可用后成为最终提交点。

## 决策

1. 首装协调器只接受 1 至 4 个由内置模板生成的安装计划和一个已验证的 `MaterializedRuntime`。计划按 host ID 排序，重复 host、config path 或资产目标在写入前拒绝。
2. 任何 install-state 已存在时，在宿主写入前返回 `INSTALL_TRANSACTION_CONFLICT`。首版协调器不把重新运行解释为升级、修复或强制覆盖。
3. 每个宿主先物化插件/Canonical Skill 资产；仅配置型宿主随后执行 JSON/JSONC 配置事务。Codex/Claude 的 `.mcp.json` 继续由插件资产 tree hash 单独管理。
4. 全部应用后，协调器先只读复核每个配置文件的完整 SHA-256 和每棵资产的 tree hash，再调用可选的宿主验证钩子。钩子用于后续接入真实宿主注册/可发现性检查，不获得提交 install-state 的权限。
5. 只有内部复核和宿主验证均成功，才构造并以“旧状态必须不存在”的条件写入 install-state。状态写入是首装的最后一步，之后不再执行可能触发事务失败的操作。
6. 任一步失败时按宿主逆序回滚；单个宿主内先回滚配置，再回滚资产。每项回滚独立尝试，一个冲突不能阻止其他无关资产清理。
7. 全部回滚成功时保留原始错误码；任何配置/资产因外部修改无法回滚时，保留用户现场并统一返回 `INSTALL_TRANSACTION_ROLLBACK_CONFLICT`。

## 结果

- 首装不会静默留下仍可安全撤回的半套宿主修改；外部修改导致的冲突现场会被保留并明确报错。
- 配置冲突、验证失败和提交前状态竞态都有自动化回滚覆盖。
- install-state 只描述已经通过提交前复核的宿主集合。
- 状态首次创建在提交后不再因临时文件清理失败误报整个事务失败。

## 安全边界

当前只读复核证明“刚写入的字节/tree hash 尚未漂移”，不等于宿主已经加载或发现插件。真实 Codex/Claude 注册、各宿主进程级探测和 doctor 集成仍需通过验证钩子接入，完成前不得开放 `install` CLI。

首装失败会撤回本次配置和资产修改，但保留已经验证的 runtime 版本目录、稳定 launcher 和 active pointer 作为未被宿主引用的本地缓存。已有状态下的 active pointer 切换与旧 runtime 恢复属于受管升级事务，不在首装协调器中猜测实现。

## 当前限制

- 不处理已有 install-state、受管目录替换、卸载或多版本迁移。
- 本 ADR 决策时不自动注册 Codex/Claude marketplace；ADR-0019 已接入 Codex 个人 marketplace 文件事务，但 Codex CLI 激活和 Claude marketplace 仍未实现，也不把内部 hash 复核描述为进程级可发现性验证。
- 不开放 `install/uninstall` CLI，不接收真实 AK/SK，不恢复密码、daemon、锁服务或 v0.2 复杂设计。

## 未采用

- 不在每个宿主完成后增量写 install-state。
- 不因单项回滚冲突停止其余回滚。
- 不把 runtime 缓存清理与宿主事务耦合，也不使用 `--force` 覆盖用户修改。
