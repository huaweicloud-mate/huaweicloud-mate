# ADR-0044：自动发现多宿主首装与复验

状态：Accepted
日期：2026-07-15

## 背景

四宿主已经各自具备显式 `install --host ...` 生命周期，多宿主首装事务也能一次提交一至四个 plan，但公开 CLI 仍强制用户选择单一宿主。这不满足 Proposed v0.3-lite 的“自动配置所有已检测 Agent”要求；同时，直接依次调用现有单宿主升级器会在第一个宿主提交后令其余宿主仍绑定旧 runtime，不能作为多宿主升级方案。

## 决策

1. `huaweicloud-mate install` 默认从发行包内已验证的四份模板发现宿主；`--host` 保留为显式兼容入口，`uninstall` 仍要求单一 `--host`，避免扩大删除范围。
2. Codex、Claude Code 和 OpenCode 必须发现可执行命令才进入自动首装；码道允许命令或固定配置路径任一存在，与提交前原生验证能力一致。路径检测只接受非符号链接的常规文件或目录。
3. 自动首装把全部可安装宿主 plan 交给既有单一事务，统一物化资产、写配置/marketplace、激活插件、执行稳定 Router 与原生宿主验证、运行一次点击式 approval probe，最后只提交一个含全部宿主的 install-state。任一步失败仍逆序回滚全部已应用宿主。
4. 自动重跑已有单宿主状态时继续复用该宿主成熟的升级器。已有多宿主状态且发行版本/manifest 未变化时，执行 host doctor 等价的完整绑定复验并运行一次 approval probe，install-state 与 active pointer 保持不变。
5. 多宿主候选版本或 manifest 发生变化时不得串行复用单宿主提交器；该缺口现由 ADR-0045 的跨宿主恢复标记、单次 pointer 切换和单次最终状态提交补齐。
6. 未发现任何支持宿主时返回 `HOST_DISCOVERY_FAILED`，不创建 install-state，也不猜测用户意图。

## 结果

- 首次安装不再要求用户逐个选择宿主，检测到的 Codex、Claude、OpenCode、码道可以一次进入同一受管状态。
- 自动化覆盖 Codex + OpenCode 双宿主首装、同版本完整复验、跨版本拒绝时 state/active pointer 不变，以及零宿主 fail closed。
- Proposed v0.3-lite 的自动多宿主“首装与同版本复验”由本 ADR 落地；跨版本协调升级由后续 ADR-0045 完成。
