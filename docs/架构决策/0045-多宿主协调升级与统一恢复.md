# ADR-0045：多宿主协调升级与统一恢复

状态：Accepted
日期：2026-07-15

## 背景

ADR-0044 已完成自动多宿主首装与同版本复验，但既有 Codex、Claude 和配置宿主升级器都会各自切换 active pointer 并写入只含单一宿主的 install-state。把它们串行调用会令第一个宿主进入候选 runtime、其他宿主仍绑定旧 runtime，既不原子也无法用现有单宿主标记恢复。

## 决策

1. 多宿主状态由专用协调器升级，不调用单宿主提交器。升级前重新绑定并复验每个宿主的旧配置、资产、marketplace/registration/activation、active pointer 与 install-state，候选 plan 不得改变固定路径或受管配置值。
2. 写入一个 `multi-host-upgrade-recovery.json`，绑定旧 state/runtime/pointer、候选 runtime，以及按固定顺序排列的全部宿主候选资产摘要。Claude 额外绑定 catalog 摘要；候选 Codex/Claude 激活成功后以 CAS 追加精确 activation evidence。
3. 先撤销受影响的旧插件 activation、Claude catalog 和发生内容变化的受管资产，再安装并逐项复验候选资产/catalog/activation。内容摘要未变化的 Canonical Skill 保留原 ownership 证据，只更新其已验证 source 绑定。
4. 全部宿主候选资源就绪后只切换一次 active pointer，执行一次四宿主稳定 Router/原生注册/点击式审批验证，最后只提交一次包含全部宿主的 install-state。install-state 是最终提交点；标记清理失败由下一次 install 复验候选后完成。
5. 最终提交前的常规失败按依赖逆序撤销所有候选资源、恢复旧 pointer/资产/catalog/activation；CLI 重装可能产生新的精确 activation/createdPaths 证据，因此允许以旧 runtime 和恢复后的真实证据 CAS 更新旧版本 state，而不伪造原字节不变。
6. 下一次自动 `install` 发现标记且 state 仍为旧摘要时，只接受资源精确匹配旧摘要、已记录候选摘要或已删除三类可证明现场，随后统一回滚。state 已是候选时，必须复验全部候选资产、注册、activation、稳定 Router 和 candidate pointer 后才能删除残留标记。任何其他内容均 fail closed。
7. 显式 `install --host` 不接管多宿主恢复；卸载在任一多宿主恢复标记存在时拒绝执行。

## 结果

- 默认 `install` 现可对二至四个受管宿主执行跨版本协调升级，同时保留单宿主成熟升级器。
- 自动化覆盖 Codex + OpenCode 成功升级、最终验证失败全局回滚、候选资产/activation 中断回滚，以及 Codex、Claude、OpenCode、CodeArts 四宿主统一升级和候选 state 已提交后的标记收敛。
- 多宿主升级不恢复 Proposed v0.2 的通用 Adapter SPI、动态 Provider 或独立 update/repair 命令；它只是四份固定模板上的有界安装事务。
