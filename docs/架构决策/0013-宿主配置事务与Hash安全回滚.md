# ADR-0013：宿主配置事务与 Hash 安全回滚

状态：Accepted
日期：2026-07-14

## 背景

ADR-0012 已把四宿主的真实配置路径、merge strategy 和固定 MCP fragment 收敛为确定性安装计划。正式串联 `install` 前，需要先实现不会静默覆盖用户配置、能够保留 JSONC 注释，并在失败时安全回滚的最小事务边界。

## 决策

1. 配置事务只接受安装计划生成的 `configPath`、`mergeStrategy`、固定 `huaweicloud-agent` entry 和单根 config fragment。fragment 不能携带其他宿主配置字段。
2. `json-object` 与 `plugin-manifest` 按严格 JSON 解析；`jsonc-object` 使用固定依赖 `jsonc-parser@3.3.1` 生成路径级最小编辑，保留现有注释、尾逗号、未知字段、缩进、换行和 UTF-8 BOM。
3. 任意层级出现重复 JSON property、非对象根、非法注释、超出 8 MiB、符号链接或非普通文件时立即停止。当前四模板不使用 `toml-table`，事务层明确拒绝它。
4. 若 `huaweicloud-agent` 不存在则插入；若值完全一致则幂等返回且不写文件、不创建备份；若同名值不同则返回 `HOST_CONFIG_CONFLICT`，不静默覆盖。
5. 修改已有文件前，先把原始字节写入权限受限的备份目录和 `0600` 备份文件并 `fsync`。新内容写入同目录随机临时文件并 `fsync`，提交前再次比较原文件 SHA-256，随后原子 rename。
6. 回滚必须同时满足：当前文件 SHA-256 等于本次安装结果，且备份 SHA-256 等于事务记录的安装前值。任一不匹配均返回 `HOST_CONFIG_ROLLBACK_CONFLICT`，保留用户现场。
7. 新建配置的回滚只在当前 hash 未变化时删除该文件；已存在配置成功恢复后删除本次临时备份。

## 结果

- OpenCode 严格 JSON 与码道 JSONC 可以共享一个有限的事务实现，而不引入通用 Adapter SPI。
- 安装期间检测到的外部修改不会被已读取的旧内容覆盖；安装后的用户修改也不会被失败回滚覆盖。
- 事务结果提供完整文件 hash、安装项 canonical hash、备份路径和创建标记，可直接作为后续最小 install-state 的输入。

## 限制

- 普通文件系统没有跨平台 compare-and-swap rename。实现会在 rename 前重新读取并比较 hash，把竞态窗口压到最小，但不能对同一用户权限下的恶意竞态提供强隔离；这延续 ADR-0011 的同用户攻击者边界。
- 本 ADR 只实现配置文件事务，不复制插件/Skills、不写 install-state，也不开放 `install` CLI。
- 插件源 `.mcp.json` 的占位值必须先在受控 staging 目录渲染；不能把占位模板当作已有用户配置强制覆盖。

## 未采用

- 不使用整文件 `JSON.stringify` 覆盖 JSONC，因为会删除注释并放大 diff。
- 不在冲突时提供 `--force`；首版必须显式报告并由用户处理。
- 不建设锁服务、常驻 daemon、通用事务日志或复杂 drift 框架。
