# ADR-0039：审批契约已验签内存编译

状态：Accepted
日期：2026-07-15

## 背景

ADR-0038 已使 companion 入口从 launcher 校验时保留的字节加载，但 signer 和父端 verifier 随后仍分别从版本目录读取七份契约 JSON。攻击者若在工件摘要校验之后替换 schema，父子可能编译到不同内容或接受未经该次校验的契约。

## 决策

1. `ContractRegistry` 增加严格的内存 JSON 文档入口。文档集合必须精确包含冻结清单中的七个文件名，不得缺失或增加；每份为 1～4 MiB 内的 UTF‑8 JSON object，且 `$id` 必须匹配内置 contract ID。
2. 正式 runtime manifest 必须显式绑定全部七份 `contracts/schema/*.json`；manifest 最多 1 MiB，只接受本地、非 symlink、有界普通 UTF‑8 JSON 文件，artifact 数量最多 128。
3. launcher 在同一轮逐文件 SHA-256 校验中保留 companion 入口和七份契约文本，构造严格版本的私有 envelope，经继承 stdin 一次性发送给 bootstrap。envelope、入口和单个工件均有 64 MiB 上限。
4. bootstrap 只把不可写的契约 JSON 文本集合绑定到子进程内存。companion signer 从该集合编译 registry；父端 verifier 从 launcher 保留的同一集合独立编译 registry，不再为本次审批按路径重读 schema。
5. bootstrap ready/error 消息只允许固定 schema、type 和阶段枚举，不包含异常文本、源码、路径或契约内容。子进程退出后父端让出一个事件循环并等待最新消息链，避免最终 IPC 结果与 exit 事件竞态。
6. 测试 fixture 的旧路径模式仅用于不具备正式 manifest 的单元测试；`fromRuntimeManifest` 固定使用已验签入口和契约 envelope。

## 结果

- 一次审批中的 signer 与 verifier 使用同一批已验签契约字节，父子仍分别编译和验证。
- 正式无交互测试证明：内存加载入口、七份契约、session ready、父端 verifier 建立及过期请求拒绝均成功，且不会打开浏览器或签发 receipt。
- 该措施不宣称抵抗能在校验前同时替换 launcher、pointer、manifest 和全部匹配摘要的同账号攻击者；发布 provenance 与四宿主私有句柄、调试和 loopback 隔离仍是发布门禁。
