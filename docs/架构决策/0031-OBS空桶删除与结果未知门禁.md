# ADR-0031：OBS 空桶删除与结果未知门禁

状态：Accepted
日期：2026-07-15

后续状态：ADR-0048 将本地 OBS provider 纳入首版能力，本文的审批与结果未知语义不变。

## 背景

本地最小 OBS Provider 已支持列举桶和创建私有桶，但尚不能覆盖资源删除。删除桶属于不可逆的破坏性操作；即使 OBS 仅允许删除空桶，网络连接在请求发出后中断时也不能安全判断服务端是否已经完成操作。

## 决策

1. 新增静态能力 `huaweicloud.obs.bucket.delete.v1`，仅接受严格桶名和必填 region，固定使用本地 OBS Provider 的 `obs_delete_bucket` 执行器绑定。
2. 能力标记为 `write + destructive + privileged`，必须经既有两阶段 `execute` 和受信 companion 点击审批；不增加第四个 Tool，也不要求密码。
3. Provider 只向固定 OBS 虚拟主机 endpoint 发送签名 `DELETE` 请求，不接受自定义 endpoint、header 或原始命令。
4. 请求发出后的超时、连接中断或响应无法验证统一返回 `OUTCOME_UNKNOWN`，不得自动重试或切换执行器。
5. `BucketNotEmpty`、桶不存在或冲突状态返回脱敏 `CONFLICT`；OBS 响应正文、AK/SK 和签名不进入 Agent 输出。
6. 自动化测试只使用受控 fetch 和无云审批 fixture，不删除真实云资源；真实空桶删除必须在隔离测试账号验收并由用户明确点击批准。

## 结果

- 自封装 OBS Provider 已覆盖查询、创建和删除的最小资源生命周期。
- 删除结果未知不会被误判为失败并自动重试，避免重复或跨执行器副作用。
- 该能力仍不是正式产品 MCP 验收证据，正式 Streamable HTTP Provider 到位后保持 capability 契约并替换执行层。
