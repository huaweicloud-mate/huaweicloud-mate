# ADR-0034：配置宿主受管升级与中断恢复

状态：Accepted
日期：2026-07-15

## 背景

OpenCode 与华为云码道已经具备首装、同版本复核和安全卸载，但跨版本仍要求先卸载。这既违反“重跑 install 完成升级”的首版约定，也会不必要地重写用户 JSON/JSONC 并丢失最初安装时保存的卸载基线。

## 决策

1. OpenCode 和码道的 MCP 配置始终指向固定 stable launcher；升级必须证明候选配置值与既有受管值完全一致，不重写配置文件，也不替换最初的 backup/`beforeSha256`。
2. 候选 Canonical Skill tree hash 与当前一致时复用现有资产；不一致时仅允许替换本次安装拥有的资产，外部预存的同内容资产不得被升级覆盖。
3. 升级按 `recovery marker -> Skill -> active pointer -> 宿主/Router/审批探针验证 -> install-state CAS` 提交。install-state 是最终提交点，状态提交后的残留 marker 在下次 install 时只做复核和清理。
4. 单一 `config-host-upgrade-recovery.json` 严格绑定 host、旧 state/pointer、候选版本/manifest 和候选 Skill hash。存在 marker 时只允许原宿主继续恢复，其他宿主安装与所有卸载均 fail closed。
5. 旧 state 尚未提交时，恢复只接受旧或候选两个已知 Skill hash以及旧或候选两个已知 active pointer；候选资产被移除，旧资产从已验签 runtime 恢复，pointer 回到旧版本。任何第三方漂移均保留现场并返回 `UPGRADE_RECOVERY_CONFLICT`。
6. Skill rollback 中途终止产生的随机 quarantine 仅在名称格式和完整 tree hash 可证明属于旧/候选资产时收敛；旧树可恢复，候选树可删除，未知内容不得删除。

## 结果

- 四宿主都支持以 `install --host ...` 完成同版本复核和跨版本受管升级。
- OpenCode/码道升级不会触碰用户未知 JSON/JSONC 字段、注释、格式或原始卸载备份。
- 强制终止恢复仍不替代码宿主真实会话验收；码道 CLI/GUI 不可用时只能证明配置和稳定 Router 进程可用。
