# ADR-0040：OBS 有界文本对象敏感读取

状态：Accepted
日期：2026-07-15

后续状态：ADR-0048 将本地 OBS provider 纳入首版能力；真实最小权限账号验收仍是发布门禁。

## 背景

首版风险矩阵要求敏感读取经过可信审批，但此前本地 OBS 替身只有普通列桶读取以及创建、删除写操作。契约状态机向量可以证明 `sensitive-read` 标签触发审批，却不能证明真实 Provider dispatch 在审批前不会访问云端，也不能证明已批准的对象内容仍受输出凭证门禁约束。

## 决策

1. 本地 OBS provider 增加 `huaweicloud.obs.object.text.read.v1`，只读取一个明确 bucket/key 的 UTF-8 文本对象。该 capability 固定标记 `read + sensitive-read` 和 `confirmationRequired: true`，不能绕过统一 companion 的点击审批。
2. endpoint 仍由代码按 region 和 bucket 固定生成，object key 逐路径段编码；拒绝空段、`.`、`..`、反斜线、控制字符和超过 1024 UTF-8 字节的 key，不接受调用方 endpoint。
3. 成功响应最多读取 64 KiB，只接受 `text/plain`、`text/csv`、`text/xml`、`application/json`、`application/xml` 及可选 UTF-8 charset；拒绝其他 charset、压缩或未知 content encoding，并以 fatal UTF-8 解码。
4. Router preview 只展示目标对象和“内容可能敏感”的影响，不在审批前调用 provider。审批消费后才通过已绑定 generation、账号、route token、provider instance 和 TTL 的进程内 session dispatch。
5. 对象正文有意进入 Agent 上下文，因此不把整个 `text` 字段声明为自动脱敏路径；但 ADR-0036 的统一输出门禁继续扫描明确凭证字段、Authorization/令牌、签名 URL、SDK/OBS 授权串和 PEM 私钥，命中时整次结果以不泄露内容的 `OUTPUT_REJECTED` 失败。
6. 读取请求的传输失败可作为只读错误报告 retryable，但 Router 不因此自动切换 executor。该实现仍是开发期本地替身，不作为正式产品 MCP 或真实云账号验收证据。

## 结果

- 本地端到端测试覆盖 `search/describe -> preview -> 点击审批 -> provider dispatch -> 输出验证`，并证明 preview 阶段没有对象读取请求。
- 独立测试证明已审批响应中的 credential-like 文本仍会被拒绝，审批不是输出安全门禁的豁免。
- 首版已有真实 Router 路径覆盖普通读取、敏感读取、带成本/权限写入和破坏性写入；正式产品 MCP、真实测试账号与四宿主隔离仍是发布门禁。
