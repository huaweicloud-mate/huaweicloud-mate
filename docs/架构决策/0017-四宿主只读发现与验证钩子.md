# ADR-0017：四宿主只读发现与验证钩子

状态：Accepted
日期：2026-07-14

## 背景

ADR-0016 已把宿主验证留在 install-state 最终提交前，但当时的协调器只能复核配置文件 SHA-256 和资产 tree hash，不能判断宿主是否能发现插件、MCP 或 Skill。注册动作会修改宿主或 marketplace 状态，不能与只读验证混在同一个未定义事务中；同时，当前环境没有可依赖的华为云码道只读枚举命令。

## 决策

1. 新增首装验证钩子，在配置和资产已应用、install-state 尚未提交时运行。钩子再次复核受管配置/资产摘要，失败沿用 ADR-0016 的逆序安全回滚。
2. 所有宿主共用稳定 launcher smoke test：以固定 Node 绝对路径执行 `current/hcloud-agent.mjs version`，并要求输出与已物化版本完全一致。
3. Codex 通过只读 `codex plugin list` 检查精确的 `huaweicloud-mate` 插件 identity；Claude Code 通过 `claude plugin list --json` 严格解析并检查相同 identity；OpenCode 分别通过 `opencode mcp list` 和 `opencode debug skill` 检查 `huaweicloud-agent` 与 Canonical Skill。
4. 华为云码道当前只接受已复核的固定 `.codeartsdoer/codearts_cli.jsonc` 和 Canonical Skill 作为配置级注册证据；若能解析到 `codearts` 可执行文件则只记录检测结果，不调用未经确认的枚举子命令，也不宣称进程已经加载配置。
5. 全部宿主检查完成后只运行一次无云副作用的受信审批探针。用户只需在 companion 页面点击批准或拒绝，不输入密码；探针失败时不提交 install-state。
6. 命令执行器只从绝对 PATH 条目解析固定命令名，解析符号链接后的普通文件；不使用 shell、不接收 stdin、禁用颜色，默认 15 秒超时且合并输出上限为 1 MiB。Windows 不执行需要命令解释器的 `.cmd`/`.bat` shim。
7. 验证钩子本身不写 marketplace、不安装插件、不修改宿主配置，也不启动真实云操作。注册必须由后续独立事务完成，成功后才能调用本钩子并提交 install-state。

## 结果

- 首装协调器已有可复用的四宿主提交前验证实现，注册缺失、宿主未发现、命令异常和审批探针失败都保留明确错误码并触发回滚。
- 只读宿主命令有超时、输出和 shell 边界，不运行可能输出完整配置或凭证的调试命令。
- 自动化测试覆盖四宿主成功路径、注册缺失、检测失败、审批失败、超时与输出超限；测试使用无云副作用的受控 runner，不替代真实宿主验收。

## 安全边界与当前限制

本 ADR 决策时 Codex/Claude 的 marketplace 注册事务尚未实现，且 Codex 个人 marketplace source 与原稳定 `pluginRoot` 不一致。ADR-0018 已明确把 Codex 目标修正为 `~/plugins/huaweicloud-mate` 并实现可回滚的个人 marketplace 文件事务；CLI 激活/卸载与 Claude marketplace 仍待后续完成。

OpenCode 的枚举结果能够证明当前 CLI 可见 MCP/Skill 名称，但不能证明宿主已完成一次真实 Router 会话。华为云码道当前只有配置级证据，必须在稳定只读枚举接口可用后补充进程级验证。四宿主真实交互、同账号进程/loopback 隔离、发布 provenance 与目录 ACL 仍是发布门禁。

后续 ADR-0030 已补充四宿主共用的真实稳定 Router/MCP 子进程握手；它证明码道配置所指向的进程可启动并只暴露冻结的三个工具，但仍不把该证据夸大为码道 GUI/会话已经加载配置。

## 未采用

- 不为四宿主引入通用 Adapter SPI、daemon、动态命令或插件注册平台。
- 不用 `debug config` 一类可能展开敏感配置的命令完成发现。
- 不把 marketplace/配置写入塞进只读 verifier，也不使用 `--force`、自动批准或密码门禁。
