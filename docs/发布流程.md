# 发布流程

当前仓库只允许从 `dev_explore` 推进开发；本文件描述未来首个公开 npm 候选的门禁，不代表已经授权发布。

## 持续集成

`.github/workflows/ci.yml` 在 `dev_explore`、`master` 和 pull request 上运行：

- Windows amd64：`windows-2025`；
- Linux amd64：`ubuntu-24.04`；
- Linux arm64：`ubuntu-24.04-arm`；
- macOS amd64：`macos-15-intel`；
- macOS arm64：`macos-15`；
- Node.js 22、`npm ci`、完整测试和生产依赖漏洞审计；
- npm pack 内容/大小、生产依赖许可和 Git 历史 secret 扫描。
- 当前源码树的开发机绝对路径、非占位用户目录、内部 endpoint 和停用规划文件检查。

GitHub Actions 均固定到完整 commit SHA，checkout 不保留写凭证。Dependabot 每周检查 npm 与 Actions 更新。

## 本地候选检查

```text
npm ci
npm run source:check
npm test
npm audit --omit=dev
npm run pack:check
npm run licenses:check
npm sbom --sbom-format cyclonedx
```

`pack:check` 只允许 `dist/`、`LICENSE`、`README.md` 和 `package.json`，并检查必需 runtime、契约和两类插件 manifest。随后它会生成真实 tarball，在专用临时目录使用 npm 缓存离线安装，通过安装后的 bin 运行 `version` 和零 deferred 的契约 Doctor，最后清理临时目录。五平台测试矩阵都会执行该消费测试，以覆盖各平台 npm bin 形态；源码映射、TypeScript 声明、测试、工作区文件和凭证文件不进入 npm 包。

## 发布前硬门禁

`npm run release:check` 必须同时证明：

1. npm 包名和发布身份已经确认；
2. `private` 已明确改为 `false`；
3. 版本不再是 development 版本；
4. `publishConfig` 保持 public + provenance；
5. KooCLI 五个平台均绑定官方页面的精确下载对象、固定 `7.2.12` 和内置 SHA-256；上游 `latest` 对象变化必须摘要失配并等待新插件版本更新绑定。

当前开发分支故意不满足这些条件，所以发布检查必须失败。

## GitHub 候选与发布

`.github/workflows/release.yml` 仅支持手动触发，默认 `publish=false`：

1. 重跑测试、漏洞、pack、许可和 release readiness；
2. 生成 CycloneDX SBOM；
3. 生成唯一 npm tarball；
4. 使用 GitHub OIDC 为 tarball 创建 build provenance attestation；
5. 上传保留 14 天的候选制品。

只有手动设置 `publish=true` 时才进入独立 `publish` job。该 job 还必须通过受保护的 `npm-production` environment 审批，并使用配置好的 npm trusted publishing 或 `NPM_TOKEN`，最终对已经验证并下载的同一 tarball 执行 `npm publish --provenance`。

创建 Git tag、合并分支或普通 CI 都不会自动发布 npm。
